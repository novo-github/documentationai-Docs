<Update label="2026-10-16" description="v1.5.102" tags={["feature", "improvement"]}>
  {/* commits: 747965a */}

  **Release date:** October 16, 2026

  ### New Features

  #### [Understand Delivery Warnings Before Changing Your Plan](/en/platform-intro/pages/assignment-gantt)

  You can now open **How does the Forecaster work?** to learn what expected times mean, how to read the colours, and when an order may finish later than shown. On **Orders & Products**, the order page, or **Assignment Gantt**, click the information icon beside **Forecaster**. In **Assignment Planner**, open **Forecaster check → How does the Forecaster work?**.

  Clearer descriptions explain delivery warnings and missing planning details. The amber status now reads **at risk**: the order is not late yet, but the remaining work barely fits or an earlier step is not planned. **Times may be too early** warns that the displayed finish may be too optimistic. For example, a step without a machine can make an order finish later than shown.

  Reading the forecast never changes your plan or delivery dates. Use the [planning workflow](/en/platform-intro/workflows/assignment-planner) to review the warnings before deciding what to change.
</Update>

<Update label="2026-10-10" description="v1.5.109–v1.5.116" tags={["feature", "improvement", "fix"]}>
  {/* commits: ea8a47d, 8303a62, 8bb1e8e, 5d5316b, 41214e8, 1bd6219, 1d39057, 71eaffd, 0ac86ac, 5fa51d2, 97cf98b, df03372, 32922b0, ef9e6ec, 7202217, 76b5a70, e856457, f61d6c8, d5d0121, 4052254, 66a98cf, cbea5d0 */}

  **Release period:** October 9–10, 2026

  ### New Features

  #### [Plan Work Without a Connected Sensor](/en/platform-intro/pages/work-centers)
  {/* feature: work-centers */}

  Use **Machines → Work centers** to review running and planned orders at workplaces without an AVA. You can select these workplaces for orders and assignments. Their cards show work instead of sensor KPIs; they do not count toward machine states or analytics.

  Administrators choose **Kind → Work center** during setup or in the machine configuration. Converting an existing machine removes its AVA assignments and stops KPI calculation. Review the confirmation before **Unassign and switch**. Follow [Add a Machine or Work Center](/en/platform-intro/workflows/add-machine) or [Configure a Machine](/en/platform-intro/workflows/machine-configuration).

  #### [Find and Update Your Reports in One Archive](/en/platform-intro/pages/report-archive)
  {/* feature: report-archive */}

  Open **Report archive** to find **Weekly**, **Monthly**, and **Export** reports. Filter by period, machine, or source, check whether a report is **Ready**, and download the available file. Scheduled reports can be delivered by email; the archive shows the delivery count.

  Select **Rebuild with current data** to check an existing report against current production records. If nothing changed, the archive tells you. If rebuilding fails, the previous version remains available. A report that takes longer to create appears in the archive when ready. Follow [Download and Update Reports](/en/platform-intro/workflows/reports).

  ### Improvements

  #### [See When an Active Shift Is Waiting to Start](/en/platform-intro/pages/machine-history)
  {/* feature: active-shift-display */}

  **Waiting for the next active shift** explains why no active shift is running yet. The next shift begins automatically at idle, production, or preparation. Until then, planned shifts from the assigned group are shown; this does not switch the machine back to scheduled shifts.

  In **Machine History**, select the shifts you want to review. Charts follow your selection, and shift details show the times. Choose **Whole day** for the full day. Follow [Review Machine History](/en/platform-intro/workflows/machine-history-review).

  #### [Switch Between Planning Queues and the Timeline](/en/platform-intro/pages/assignment-planner)
  {/* feature: planner-view-switch */}

  Use the view switch in **Assignment Planner** or **Assignment Gantt** to move between queues and the timeline. Review dates in the timeline and return to the planner to change assignments. Follow [Plan Machine Assignments](/en/platform-intro/workflows/assignment-planner).

  ### Fixes

  #### [Compare Shifts with Correct Cycle and Energy Figures](/en/platform-intro/pages/hall-plan)
  {/* feature: shift-cycle-energy-corrections */}

  Live-shift cycle counts could appear empty while cycles were counted in the previous shift. The comparison now places cycles in the correct shift. Shift energy totals now follow the company's local shift times; previously, they could cover a different time window. This also corrects energy totals in [Machine History](/en/platform-intro/pages/machine-history).
</Update>

<Update label="2026-10-08" description="v1.5.105–v1.5.108" tags={["feature", "improvement"]}>
  {/* commits: 3a5c8dd, 4f44e8f, 87405e8, 0318a78, ff47139, 43a80ee, a87a9e5, 58ee9d6 */}

  **Release period:** October 7–8, 2026

  ### New Features

  #### [Let Shifts Follow Machine Activity](/en/platform-intro/pages/machine-configuration)
  {/* feature: active-shifts */}

  Administrators can now open the machine configuration and select **Shifts → Active shift**. A shift starts automatically when the machine begins idle, production, or preparation. Set **Minimum shift length**, **Stop that ends a shift**, and **Maximum shift length** to control its end. Before the minimum is reached, a shorter stop such as lunch stays within the shift as off time. After the minimum, the first stop ends it. At the maximum, a new shift starts even if work continues; the limit is 24 hours.

  Switching on removes scheduled shifts from today onward, but keeps shifts already recorded today. The assigned shift group stays in place and is unused. Switching off ends the running active shift immediately and creates scheduled shifts from the group from today. Some alert rules do not fire for these machines; review their notices. Follow [Configure a Machine](/en/platform-intro/workflows/machine-configuration).

  #### [Confirm a New Email Before Your Sign-in Address Changes](/en/platform-intro/pages/user-profile)
  {/* feature: verified-email-change */}

  Open **Profile → Change email**, enter **New email**, and select **Send verification**. Open the link sent to the new address and select **Confirm email change**. Keep using your current email until confirmation, then sign in with the new one.

  While confirmation is pending, use **Resend** after the displayed wait or **Cancel change**. Administrators can also request changes for users who are not operators from user management; the user must still confirm the new address. Follow [Change Your Email Address](/en/platform-intro/workflows/change-email).

  ### Improvements

  #### [Recognize the Product Running on Each Machine](/en/platform-intro/pages/hall-plan)
  {/* feature: hall-plan-product-information */}

  In the Hall Plan display settings, choose **Product information → On** to show the active order's product image, product name, and operation sequence (#) next to the machine image. The product must have an image. Order names and positions help you identify the work.

  With **Off**, or without a product image, the operation sequence appears in the order card instead. Order and operation priority always appear in the order card. You can also click the state-pattern icon to see examples. Follow [Set Up a Hall Plan Display](/en/platform-intro/workflows/hall-display-setup).
</Update>

  ### New Features

  #### [Catch Missing Production Entries with the PDA Assistant](/en/platform-intro/pages/data-acquisition)
  {/* feature: pda-assistant-warnings */}

  The **PDA Assistant** warns about production without an order, forgotten running orders, missing downtime reasons, and stale live data. Administrators enable it in the machine configuration under **PDA Assistant → Enable warnings on this machine** and choose each warning's delay, severity, and sound.

  On the PDA page, select **View all warnings** to review the issues and available actions. Snoozing hides and silences a warning temporarily; it returns if the problem remains. Follow [Run Data Acquisition](/en/platform-intro/workflows/data-acquisition) or [Configure a Machine](/en/platform-intro/workflows/machine-configuration).

  #### [Build and Review Alert Rules from Templates](/en/platform-intro/pages/automator)
  {/* feature: automator-templates-review */}

  Administrators can open **Automator**, choose **Start from a template**, and adapt an alert for slow cycles, scrap, delays, or a missing sensor signal. Nothing is created until you review and save. **Review → What this alert will do** explains the conditions, recipients, timing, and escalation.

  Missing recipients are called out: the alert still appears in Events, but nobody receives an email. Escalation can notify selected recipients when an alert is not handled in time. Open an event to inspect its details. Follow [Create an Automator Rule](/en/platform-intro/workflows/automator-rule-creation).

  #### [Set a Priority for an Individual Operation](/en/platform-intro/pages/assignment-planner)
  {/* feature: operation-priority */}

  In **Assignment Planner**, select a dashed **OP** chip to change **Operation priority** independently of **Order priority**. Filter by either priority or both; when both filters are set, work must match both.

  In Order Upload, **Initial operation priority (new operations)** supplies a value when the operation priority cell is empty or no column is selected. Leave the initial value empty to use 100. Existing priorities stay unchanged on re-import. See the [planning workflow](/en/platform-intro/workflows/assignment-planner) and [import workflow](/en/platform-intro/workflows/order-upload-planner).

  ### Improvements

  #### [Choose the Right Dates and View for Planning](/en/platform-intro/pages/assignment-planner)
  {/* feature: planner-dates-guide */}

  In **Assignment Planner**, open the information icon for **Assignment Planner Guide** to understand filters, sorting, and moving cards. Cards can show **Operation Planned Start** and **Operation Planned End**. Use operation dates to sequence individual steps, or order dates to keep an order's steps together.

  On the order page, **Group by → Operation** or **Machine** changes how you review the work. In [Orders & Products](/en/platform-intro/pages/orders-products), the planned/actual date choice determines whether the date filter searches scheduled or recorded work. Follow [Plan Machine Assignments](/en/platform-intro/workflows/assignment-planner).

  #### [See What a Re-import Keeps and What Needs Review](/en/platform-intro/pages/erp-upload-planner)
  {/* feature: reimport-protection */}

  In Order Upload, open **What a re-import changes for existing orders** to review which values stay and which may update. Empty cells keep existing values. Production history is never changed, and missing rows delete nothing.

  Operations with recorded work stay on their current machine and are still imported. Choose **Keep both** if they should also run on the new machine. Quantities already split across machines stay in place and are marked for planner review. Check the warnings before and after import using the [import workflow](/en/platform-intro/workflows/order-upload-planner).
</Update>

  **UI-Build commits:** `2dbb32c`, `3aa62c3`, `fda9521`

  **Release period:** September 15–16, 2026

  ### New Features

  #### [Review What an Order Import Will Change](/en/platform-intro/pages/erp-upload-planner)

  Order Upload now helps you check the impact of an import before confirming it. After uploading your file and reviewing the column mapping and preview, open **What this import will change** to see counts of new, updated, and existing records across orders, products, customers, operations, and assignments.

  Expand the row-by-row details to see which schedules will change, which operations and assignments will be created, and which durations will be recalculated. Confirm the import once you have reviewed the proposed changes.

  #### [Resolve Scheduling Conflicts During Import](/en/platform-intro/pages/erp-upload-planner)

  If an imported operation is already scheduled elsewhere, Order Upload now groups the conflict under its order and explains the reason, such as an assignment that already has recorded production. Review each conflict and choose the appropriate action:

  - **Move to [new target]** to apply the assignment from the file.
  - **Keep on [current target]** to retain the existing assignment.
  - **Keep both** to keep assignments at both targets for parallel work.

  Conflicts that cannot be resolved in the import review are flagged for manual resolution in the **[Assignment Planner](/en/platform-intro/pages/assignment-planner)**. After import, a summary shows which decisions were applied and explains any that could not be applied, for example because production started after your review.

  #### [Highlight Important Fields on Planning Cards](/en/platform-intro/pages/assignment-planner)

  In the **Assignment Planner** or the [order operation panel](/en/platform-intro/pages/order-detail), open **Highlight** and select the fields you want to emphasize. Fields are grouped by Order, Work Order, Product, Operation, Planning, and Assignment.

  Your selected fields are highlighted across the cards, making details such as priority, due date, or customer easier to find when scanning a busy plan.

  ### Improvements

  #### [Clearer Operation Notes and Descriptions](/en/platform-intro/pages/order-detail)

  Notes and descriptions are easier to read and edit in Work Order Notes and the order timeline. Empty fields now show a visible prompt so you can see where to add information for the next person working on the operation.
</Update>

<Update label="2026-04-30" description="v1.5.60" tags={["feature", "improvement"]}>
  **UI-Build commit:** `ad93cfa01`

  **Release period:** March–April 2026

  ### New Features

  #### User Permissions Editor

  Administrators can manage page and machine access from the Admin Panel.

  - Open a user record and select **Edit Permissions**.
  - Select the platform pages and machines the user can access.
  - Save the changes so they apply to the user's next session.

  #### Chat History

  The AI assistant has a dedicated page under **Workspace → Chat History**.

  - Reopen saved conversations.
  - Star, rename, or delete conversations.
  - Review answers in the documentation context from which the conversation started.

  ### Improvements

  #### Orders & Products

  The order table includes additional planning and production fields:

  - Customer and priority
  - Planned and actual durations
  - Average cycle time
  - Cycle-time and setup-time deviation
  - Production interval count

  Column visibility preferences are saved for later sessions.

  #### Assignment Planner

  - Search the unassigned operations queue by order, product, or operation.
  - Filter by order tags and priority.
  - Review and edit operation or assignment notes from the planner.

  #### ERP Upload Planner

  - Import order tags with order data.
  - Choose standard or industry-minute interpretation for time fields.
  - Limit an import to orders that already have a machine assignment.
  - Review upload progress and schedule warnings before confirmation.

  #### Data Acquisition (PDA)

  - Operation sequence numbers appear on job chips.
  - Starting or stopping production updates the related order status.
  - An over-production prompt can help operators review order completion.
  - Operation and assignment notes are available from the PDA page.

  #### AI Chat Sidebar

  The assistant can provide documentation-based guidance about the current page, available actions, workflows, and settings.

    Page and machine availability depends on the permissions assigned to the user.
  </Callout>
</Update>
