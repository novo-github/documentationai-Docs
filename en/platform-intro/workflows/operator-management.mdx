## Goal

Keep the machine operator list accurate so scheduling and production tracking reflect the right people.

## Before You Begin

<Callout kind="info" title="Workflow access">
- Required access: Admin only.
- Entry points: `/admin-panel`
</Callout>

Begin on the [Admin Panel page](/en/platform-intro/pages/admin-panel).

### Preconditions
- The user has admin access.

## Steps

<Steps>
  <Step title="Open the machine operator management area" icon="arrow-right" title-type="p">
    Open **Admin Panel → Configure Shifts and Scheduling → Machine operators**. These accounts have the Machine operator role.
  </Step>
  <Step title="Add a new machine operator or edit an existing one" icon="arrow-right" title-type="p">
    Choose **Add machine operator**, or open an existing account to edit it.
  </Step>
  <Step title="Save the machine operator details" icon="arrow-right" title-type="p">
    Save the account details. When editing, choose **Update machine operator**. The confirmation uses your selected language.
  </Step>
  <Step title="Use the updated machine operator list" icon="arrow-right" title-type="p">
    Use the updated machine operator list in planning or machine-related pages.
  </Step>
</Steps>

## Deactivate a machine operator

When a machine operator no longer needs access, open their record in machine operator settings and use the deactivation action. Access is deactivated immediately, while previous shifts, labels, and assignments remain available in the production history.

The machine operator list shows active machine operators only. A deactivated machine operator disappearing from that list does not mean their historical records have been deleted.

## Generate a Replacement Password

Open the existing machine operator record and choose **Edit machine operator**. For an eligible machine operator, use the action to generate a new password. Copy or download the generated credentials before closing the window: they are displayed only once.

Generating a replacement password ends the machine operator's active sessions. The machine operator must sign in again with the new password. Use the existing record for recovery so the person's production history stays together.

## Send an Email Verification Message

From the machine operator's record, explicitly request or resend the confirmation email when verification is needed. Creating or editing a record, or generating a password, does not automatically send a verification email.

A machine operator whose email is not yet verified can still sign in and use their assigned access. Email verification and machine operator activation are separate: verification confirms the email address, while activation determines whether the machine operator has access.

## Review the Role Before Promoting

**Promote to user** gives the machine operator access to all machines regardless of their existing machine list. Review [roles and access](/en/platform-intro/concepts/roles-and-access) before using it. Use [Invite Users and Manage Permissions](/en/platform-intro/workflows/user-access-management) for ordinary team invitations and page permissions.

## Decision Points

- Whether the user should create a new machine operator or update an existing one.
- Deactivate a machine operator to end access while retaining history; use password recovery when an active machine operator needs new credentials.

## Expected Result

Machine operators are available for scheduling and production-related workflows.

## Common Problems and Edge Cases

- Old or duplicate machine operator records make planning harder to trust.
- A new machine operator may exist in the platform before being assigned anywhere.
