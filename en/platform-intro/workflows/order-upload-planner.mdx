## Goal

Bring external order data into the platform in a controlled, preview-first flow.

## Before You Begin

<Callout kind="info" title="Workflow access">
- Required access: Admin or User with access to **ERP Uploads**. AI suggestions also require AI access.
- Open **Planner → ERP Uploads**.
</Callout>

Begin on the [ERP Upload Planner page](/en/platform-intro/pages/erp-upload-planner).

### Preconditions
- The upload file is ready.
- You know which spreadsheet columns represent orders, products, dates, and machines, and which time convention the file uses.
- You can review the existing production plan if the file proposes changes to scheduled operations.

## Steps

<Steps>
  <Step title="Upload the spreadsheet file" icon="arrow-right" title-type="p">
    Select your order file. Check its file name, row and column count, and sample contents to confirm you selected the right data.
  </Step>
  <Step title="Correct source values if needed" icon="arrow-right" title-type="p">
    Select **Expand to edit** to correct individual values or paste matching groups of values from Excel. Review the changed-cell count and save your corrections; the preview highlights saved changes. Column headings and row counts cannot be changed here. Closing without saving discards unsaved corrections and leaves the original file unchanged.
  </Step>
  <Step title="Map columns and machine references" icon="arrow-right" title-type="p">
    Map the source columns, including order tags where needed. For operation materials, follow [include parts lists](/en/platform-intro/workflows/order-upload-planner#parts-lists). Reuse a saved mapping if it matches this file. Match external machine names or codes to the correct machines.

    For AI help, choose **Map Columns → Suggest mapping**. Read **Please check**, select the suggestions you want and choose **Apply (n)**. A suggestion uses 1 AI credit; a failed suggestion costs nothing. Check the preview afterwards; see [review a suggested mapping](/en/platform-intro/pages/erp-upload-planner#suggest-mapping).

    Map **Order priority** and **Operation priority** separately. Set **Initial order priority (new orders)** and **Initial operation priority (new operations)** for empty cells or when no priority column is selected. Leave the initial operation priority empty to use 100. Correct marked values: operation priorities must be whole numbers of zero or more. Initial values do not replace invalid entries, and existing priorities never change on re-import.
  </Step>
  <Step title="Set number formats, units and cycle conversions" icon="arrow-right" title-type="p">
    In **Map Columns**, find **Numbers in the file** directly below **Planned Quantity**. Choose **German 1.234,5** if 6.480 means six thousand four hundred eighty. For times in milliseconds, choose **Milliseconds (ms)**, also when the file writes “ms”; 140 ms then shows as 0.14 s.

    Enter a **Default unit** such as Stk or Paket beside **Quantity Unit** if needed. For a press making sheets that form a package, follow [the cycle import steps](/en/platform-intro/workflows/order-upload-planner#cycle-import).
  </Step>
  <Step title="Choose where imported work enters the queue" icon="arrow-right" title-type="p">
    In **Operation Fields**, directly below the **Operation Description** row, review **New operations in the queue**. Keep the preselected **By sorting**, or choose **At the start** or **At the end**. The choice applies to machine queues and hall pools. **At the start** places work behind running operations.

    For **By sorting**, read the rules shown below. Choose **Change** to edit them for this import. Use **Use company sorting** when available to follow company rules again. Without your own or company rules, the import uses **Order priority** ↓, then **Delivery Date** ↑. Save the mapping to reuse your placement choice and rules.

    Open the information icon to see how new work fits around manually arranged work. Existing operations keep their relative order. Placement never changes priorities or dates. See [queue placement](/en/platform-intro/pages/erp-upload-planner#queue-placement) for examples and limits.
  </Step>
  <Step title="Check import scope and time interpretation" icon="arrow-right" title-type="p">
    If needed, limit the import to orders that already have a machine assignment. Choose standard or industrial-minute interpretation to match the file's time convention. Review the explanations of changes to preparation and production times and the affected rows. If the preview warns about rows without a machine, match their machine values now or plan them later under **Planner → Unassigned**. Until planned, those operations cannot start on the PDA page.
  </Step>
  <Step title="Review the preview and proposed changes" icon="arrow-right" title-type="p">
    Run the preview and review schedule warnings. Check **New operations in the queue:** in the summary before importing. Open **What this import will change** to compare counts of new, updated, and existing orders, products, customers, operations, and assignments. Expand the row-by-row details to check schedule changes, new operations and assignments, and recalculated durations. Correct the file or mapping if the proposals do not match your intent.

    Read **What a re-import changes for existing orders** and the marked cells that keep existing values. Compare **Planned quantity (machine)** with **Planned quantity (work order)**. Quantities split across machines are kept and marked for planner review. Empty update cells keep current values; protected values and production history stay unchanged. Missing rows delete nothing.
  </Step>
  <Step title="Review scheduling conflicts" icon="arrow-right" title-type="p">
    For each conflict grouped under an order, read the reason and choose **Move to [new target]** to apply the file's assignment, **Keep on [current target]** to retain the existing assignment, or **Keep both** for parallel work at both targets. Operations with recorded work stay on their current machine and are still imported. Choose **Keep both** if the operation should also run on the new machine. If the review marks a conflict for manual resolution, use the [Assignment Planner](/en/platform-intro/pages/assignment-planner).
  </Step>
  <Step title="Confirm the import" icon="arrow-right" title-type="p">
    After reviewing the changes and conflict decisions, choose **Import (n)**. If **Save the mapping?** appears, review its change list. Choose **Save and import** to keep the mapping for next time, or **Import without saving** to use it only for this import. Closing the question imports nothing. If saving fails, nothing is imported; retry saving or choose to import without saving. Follow the import progress.
  </Step>
  <Step title="Check the applied results" icon="arrow-right" title-type="p">
    Read the outcome summary to see which decisions were applied. With **By sorting** or **At the start**, check the separate placement line for the number of operations and queues affected. It appears when work was placed, including alongside conflicts, skipped rows, or warnings. Moved operations count too. If a decision could not be applied, review its explanation and check the affected operation in the Assignment Planner. Production may have started after you reviewed the conflict. Check the updated machine-quantity count and any import warnings. Review quantities split across machines in the planner before adjusting them.
  </Step>
</Steps>

## Confirm the Four Import Stages

**Upload File → Map Columns → Review & Assign Machines → Review & Save** uses CSV, XLS, or XLSX. Map the order, product, planned start and planned end. Choose **ALL Units / 1 Unit** or, with cycles per product, **1 cycle** as the production-time basis. Choose ordinary or industrial minutes and the initial priorities for new records with empty priority cells. Choose which rows to import: **All rows** or **Machine assigned**. Initial operation priority defaults to 100. Save Mapping is per user; manual machine/hall-pool assignment overrides mapping, and **Reset selected rows** removes the manual choices for the selected rows and restores their column mapping.

Run **Check** as a dry run. **NEW / NEU**, **CHG / GEÄ**, and **IMPACT** show creation, update, and affected planning calculations. Check saves nothing. If data changes, run Check again before **Import (n)**.

Rows without scheduling or with start after end are not processed. Re-import matches product, order, work-order product, operation sequence, and machine assignment. Empty update cells preserve values; existing priorities, protected fields, and production history are unchanged. Missing file rows do not delete records. Operations with recorded work cannot move; ambiguous multiple-target conflicts need manual planner review.

**Example:** If an imported planned time of 100 minutes covers 50 units, choose ALL Units. If it is 2 minutes per unit, choose 1 Unit. Choosing the wrong option changes the planned duration.

## Include Parts Lists in the Import

<Steps>
  <Step title="Prepare one list per operation" icon="arrow-right" title-type="p">
    In your order spreadsheet, put each operation’s parts in one cell. For Excel files (XLSX), semicolons between parts are the safest choice. For CSV files with semicolons between columns, use pipes between parts. One part per line within the cell also works. Use a separate column for the product’s revision, such as A0; put individual part revisions in their part lines. Only the first 200 parts in a cell are imported. Further parts are left out.
  </Step>
  <Step title="Map the parts and revision columns" icon="arrow-right" title-type="p">
    In **Map Columns → Operation Fields**, map one column to **Parts list** and optionally one to **Revision**. To add lists to existing work, re-import your current export with these mappings. Old notes remain unchanged.
  </Step>
  <Step title="Choose the separator and check the example" icon="arrow-right" title-type="p">
    Directly below **Parts list**, set **Parts separated by** to **Automatic**, **Comma**, **Semicolon ;**, **Pipe |** or **Line break**. Match the choice to your file using the [separator guide](/en/platform-intro/pages/erp-upload-planner#parts-lists). Check the first list’s part count and example below the choice. If a description is split or several parts stay together, adjust the choice or correct the cell before continuing.
  </Step>
  <Step title="Review new lists and changed versions" icon="arrow-right" title-type="p">
    In step 3, review each row’s **Parts list**: it shows the part count and each part on its own line. Run the import check and look for **Parts lists** in **What this import will change**. It appears when at least one list will be created or updated. Review the highlighted parts-list and revision columns. A changed revision opens every part again. With the same revision, unchanged lines keep their ticks.
  </Step>
  <Step title="Import and inspect an operation" icon="arrow-right" title-type="p">
    Complete the usual review and choose **Import (n)**. Open an affected operation’s list in the Planner or on its PDA card. Check the parts and revision. A changed import replaces a manually edited list; an import unchanged from the previous import leaves manual edits and ticks intact.
  </Step>
</Steps>

Changing only the separator leaves a previously imported list unchanged when its cell text and product revision stay the same. To correct that saved list, ask an Admin to [edit it](/en/platform-intro/workflows/parts-lists#edit-list).

Blank parts cells, including the placeholder “keine Daten vorhanden”, leave lists alone. They do not remove them or change their revision. A blank or unmapped revision keeps the revision from the previous import, if any. See [parts-list import rules](/en/platform-intro/pages/erp-upload-planner#parts-lists).

## Import Cycle Quantities and Times

Use this when one product takes several machine cycles, for example 162 sheets per package.

<Steps>
  <Step title="Set cycles per product" icon="arrow-right" title-type="p">
    In **Map Columns**, map **Cycles per product** or enter a fixed number greater than zero. For a press making one sheet per stroke and 162 sheets per package, enter 162.
  </Step>
  <Step title="Choose what the quantity counts" icon="arrow-right" title-type="p">
    Once cycles per product is set, **Planned quantity counts cycles** appears. Choose **Yes** if the file counts sheets: 6,480 sheets become 40 packages. Choose **No** if the file already counts packages.
  </Step>
  <Step title="Set the time unit and basis" icon="arrow-right" title-type="p">
    Choose **Milliseconds (ms)** for millisecond times, also when the file writes “ms”. Under **Planned production time for**, choose **1 cycle**, which appears once cycles per product is set. At 140 ms per stroke and 162 strokes per package, the result is 22.68 seconds per product.
  </Step>
  <Step title="Check conversions before importing" icon="arrow-right" title-type="p">
    In step 3, check the calculations and machine assignments. Fill in any value marked **Cycles per product missing**; a warning about a quantity that is not a whole number still allows import. Run **Check**, review any conflicts and choose **Import (n)**.
  </Step>
</Steps>

## Decision Points

- Whether to reuse a saved mapping, review an AI suggestion or map columns yourself.
- Whether the file counts products or machine cycles, and which number format and time unit it uses.
- Whether to save changed mappings for the next import or import without saving them.
- Whether imported work should follow sorting rules, enter at the start, or stay at the end of each queue.
- Whether the preview is ready to import or needs correction first.
- Whether to move an existing assignment, keep its current target, or retain both targets for parallel work.

## Expected Result

The upload creates, updates, or reuses platform records according to the reviewed mapping. The outcome summary confirms which conflict decisions were applied and identifies decisions that could not be applied.

## Common Problems and Edge Cases

- A mapping saved before the placement choice existed starts with **By sorting**. Select **At the end** if you want the previous import behaviour.
- A repeat import that only updates an existing assignment does not move it.
- Missing required columns will block a useful preview.
- Both **Save Mapping** buttons are unavailable when nothing changed. Saving a mapping never imports orders.
- Fill in any value marked **Cycles per product missing**. A warning about a quantity that is not a whole number still allows import.
- If AI suggestions are unavailable or credits are used up, map the columns yourself.
- Match machine names from the file before importing.
- Users may need to re-upload after correcting spreadsheet structure or data format issues.
- If preparation or production times look wrong, check the affected row and the standard or industrial-minute interpretation before confirming.
- A conflict may require manual resolution, or its decision may no longer be applicable because production changed after review. Follow the explanation and inspect the affected operation in the Assignment Planner.
