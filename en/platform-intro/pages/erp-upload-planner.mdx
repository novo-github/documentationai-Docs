## Overview

**Access:** Admin or User with access to **ERP Uploads**. [Roles and access](/en/platform-intro/concepts/roles-and-access).

Import spreadsheet-based orders into the Watchmen Platform. Review the source file, match its columns to order fields, and check how the import will affect your existing production plan before confirming it.

## Access

<Callout kind="info" title="Access details">
Open **Planner → ERP Uploads**. AI suggestions also require AI access.
</Callout>

## What You Can See

- The selected file's name, row and column count, and a sample of its contents.
- Column mappings and tools for matching external machine names or codes to your machines. Hints start with **Example:** so you can distinguish them from your file’s columns.
- A preview, time-setting explanations, schedule warnings, and upload progress.
- A summary of proposed changes and scheduling conflicts, followed by the results after import.

Open ⓘ beside a setting to understand its effect; see [Help on every page (ⓘ)](/en/platform-intro/concepts/field-help).

## What You Can Do

- Upload a spreadsheet and correct values before importing.
- Map columns to order fields, including order tags, and reuse saved mappings where appropriate.
- Match machine references and, if needed, limit the import to orders that already have a machine assignment.
- Choose the time interpretation, review changes, and decide how to handle scheduling conflicts.
- Confirm the import and check which changes were applied.

## Review and Correct the File

Select **Expand to edit** in the file preview to open the full file view. You can correct individual cells or paste matching groups of values from Excel. The editor shows how many cells you have changed; saved corrections are highlighted in the preview.

Column headings and row counts stay fixed. To change the file structure, correct the source spreadsheet and upload it again. Closing the editor without saving discards unsaved corrections and leaves the original file unchanged.

<a id="suggest-mapping" />

## Suggest and Review a Mapping

Admins and Users with access to **ERP Uploads** and AI access can use **Suggest mapping**. Load a file to see the button in **Map Columns**.

For example, a work-center column containing S1600104 can be matched to machine S160.01.04 despite the different spelling. The match shows **Sure**; point at it to see the reason “Same code”.

A suggestion uses 1 AI credit; a failed suggestion costs nothing. It shares column names, a few examples and the full value list for columns with few different values. If AI access or credits are unavailable, you can map the columns yourself.

In **Suggested mapping**, read **Please check** warnings and review the proposed columns, machines and settings:

- **Sure** and **Likely** suggestions usually start ticked; **Unsure** suggestions do not.
- **Cycles per product**, **Planned quantity counts cycles** and **1 cycle** start unticked because they change quantities or times.
- Tick the lines you want and choose **Apply (n)**. Nothing changes before you apply.

Check the preview afterwards. Applying does not save the mapping or import orders. If there is nothing new, you see “The suggestion matches your current mapping.”

<a id="save-mapping" />

## Save and Reuse Your Mapping

Use **Save Mapping** at the top or bottom of **Map Columns** to keep your columns, machines and settings for next time. After loading another file, choose **Load Mapping** to use them again.

Both save buttons are unavailable when there are **No changes to save**. When you save, the confirmation lists your changes. If this file lacks a saved column, its saved choice is kept; choosing a replacement saves that new choice instead.

After checking the rows, choose **Import (n)**. If your mapping changed, **Save the mapping?** offers these choices:

| Choice | What happens |
| --- | --- |
| **Save and import** | Saves your mapping, then imports the rows. If saving fails, nothing is imported. |
| **Import without saving** | Imports with your current choices and keeps the previously saved mapping for next time. |
| Close the question | Returns to the review without importing. |

Saving a mapping alone never imports orders. Follow the [import workflow](/en/platform-intro/workflows/order-upload-planner).

<a id="parts-lists" />

## Import Parts Lists per Operation

In **Map Columns → Operation Fields**, optionally map one source column to **Parts list** and one to **Revision**. One import row represents one operation, with its parts in one cell. Directly below **Parts list**, choose **Parts separated by** to match the cell’s contents.

| Choice | How parts are separated |
| --- | --- |
| **Automatic** | Uses line breaks if the cell has any. Otherwise, splits at a comma followed by a space and the next part’s quantity. |
| **Comma** | Splits at every comma followed by a space. Decimal commas such as 11,00 stay intact; commas followed by spaces in descriptions also split the text. |
| **Semicolon ;** | Splits at semicolons; commas in descriptions stay intact. |
| **Pipe &#124;** | Splits at pipe characters (&#124;); commas in descriptions stay intact. |
| **Line break** | Splits only at line breaks within the cell. |

Every choice also separates parts at line breaks. For Excel files (XLSX), semicolons are the safest choice. If your CSV file uses semicolons between columns, use pipes between parts instead.

For example, **Automatic** reads “60 ST Distanzhülse (Ref: B0), 120 ST O-Ring D 11,00 x 2,00” as two parts. Item numbers are not required. “Schraube, verzinkt” stays one part because the comma is not followed by a quantity.

Check the example right below the choice. For a first list in row 4 containing five parts, it shows **Example (row 4): 5 parts**, then the first two parts, then **+3 more**. It updates as soon as you pick another separator. If a long cell containing several parts shows **1 part**, the separator does not fit the file. In step 3, each row’s **Parts list** shows the count and parts on separate lines; the same unsplit cell also shows **1 part** there. If the example says there is no row with a parts list, check the selected column and its contents. Only the first 200 parts in a cell are imported. Further parts are left out.

**Revision** is the revision of the product being made, usually imported from a column such as “Ref. Stand”; put a single part’s revision, such as “(Ref: B0)”, in that part’s line. A cell containing “Ref.Stand: A0” is shown as A0.

A changed list or revision creates a new version. Exactly unchanged lines keep their ticks when the revision stays the same. A changed revision opens all parts again. A repeat import with the same list and revision as the previous import leaves manual edits and ticks alone. A later changed import becomes the current list, replacing manual edits. If the parts cell’s text and revision match the previous import, choosing another separator alone does not create a new version or change ticks. To correct the saved list in that case, an Admin can [edit it by hand](/en/platform-intro/workflows/parts-lists#edit-list).

A blank parts cell leaves the list alone, even if a revision is supplied. The placeholder “keine Daten vorhanden”, with or without surrounding asterisks, also counts as empty. To remove a list, an Admin must clear it by hand. A blank or unmapped revision keeps the revision from the previous import; without a previous import, no revision is supplied.

**What this import will change** shows **Parts lists** when lists will be created or updated. A first list for an operation is counted under **New**, a new version of an existing list under **Updated**. A **Parts list** change highlights the two mapped columns in the preview.

To add lists to existing work, re-import your current order export with the parts column mapped to **Parts list** and the “Ref. Stand” column to **Revision**. Existing notes stay as they are; parts previously stored in notes are not copied automatically. Follow [import parts lists](/en/platform-intro/workflows/order-upload-planner#parts-lists).

## Understand Time and Priority Settings

Time fields can use standard or industrial-minute interpretation. Choose the convention that matches your source data. The upload review identifies the affected row and explains when a time value or the **Industrial minutes** setting changes preparation or production time. Check these explanations before confirming the import.

Priority names, numbers, and colors follow the company levels configured in the [Admin Panel](/en/platform-intro/pages/admin-panel). These levels are shared with order management and the Assignment Planner, so imported priorities can be reviewed consistently across the plan.

<a id="import-numbers" />

### Number Format and Default Quantity Unit

In **Map Columns**, find **Numbers in the file** directly below **Planned Quantity**. Numbers your Excel file stores as numbers are always read correctly; this choice only matters for numbers written as text, for example in CSV files.

| Choice | Example |
| --- | --- |
| **Automatic** | Guesses each value: 6.480 is read as six point four eight. |
| **German 1.234,5** | 6.480 is read as six thousand four hundred eighty. |
| **English 1,234.5** | 6,480 is read as six thousand four hundred eighty; 6.48 stays six point four eight. |

The page may suggest “The numbers look German (1.234,5).” with **Use German**, or “The numbers look English (1,234.5).” with **Use English**. Choose the button to use that format, then check quantities and times in the preview.

Beside **Quantity Unit**, enter a **Default unit** such as Stk or Paket, up to 20 characters. It fills missing units for new products. A unit already in the file takes precedence; existing products keep their unit.

<a id="cycle-import" />

### Milliseconds and Cycles per Product

Choose **Milliseconds (ms)** as the time unit when your file gives times in milliseconds, also when the file itself writes “ms”. 140 ms then shows as 0.14 s.

Map **Cycles per product** to a column or enter a fixed number greater than zero. The fixed number fills missing values. For a press making one sheet per stroke and 162 sheets per package, enter 162 when the product is a package.

Once cycles per product is set, these choices appear:

- **1 cycle** under **Planned production time for**: use it for time per machine cycle. 140 ms × 162 becomes 22.68 seconds per product.
- **Planned quantity counts cycles**: choose **Yes** if the file counts cycles. 6,480 ÷ 162 becomes 40 products. Choose **No** if the file already counts products.

Step 3 shows the calculations. A missing cycles value marks the row with **Cycles per product missing**. A result that is not a whole number of products shows a warning, but the row can still be imported. Follow [the cycle import steps](/en/platform-intro/workflows/order-upload-planner#cycle-import).

### Initial Priorities for New Work

Map **Order priority** and **Operation priority** separately. In the column-mapping step, **Initial order priority (new orders)** and **Initial operation priority (new operations)** supply values for new work when a priority cell is empty or no priority column is selected. Leave the initial operation priority empty to use 100.

Operation priorities must be whole numbers of zero or more. Text, fractions, and negative values are marked for correction; the initial value does not replace them. Non-numeric order priorities are also marked. Re-importing never changes the priority of existing orders or operations.

## Choose Where Imported Work Enters the Queue

In **Map Columns → Operation Fields**, find **New operations in the queue** directly below the **Operation Description** row. **By sorting** is first and preselected. A saved mapping without a placement choice also starts with **By sorting**.

| Choice | Where the imported work goes |
| --- | --- |
| **By sorting** | Behind the last active operation that comes before it or is equal under the selected rules, never ahead of running work. Existing operations are not re-sorted. |
| **At the start** | At the front, behind running work. |
| **At the end** | At the back, as imports did previously. |

With **By sorting**, read the rules below the choice. Choose **Change** to edit them for this import. The import uses its own saved rules first, otherwise the company’s rules. Without either, it uses the standard rules: **Order priority** ↓, then **Delivery Date** ↑. **By sorting** is available even without company sorting.

When company rules exist, **Use company sorting** restores them and follows the company sorting again. A tick shows when the rules already match. **Company sorting:** appears when the rules match the company sorting. **Own sorting:** identifies rules chosen for the import that differ from the company’s; **Sorting:** appears for the standard rules when no company sorting exists. Removing all your rules also restores the company rules or the standard rules.

**Save Mapping** saves the placement choice and any rules chosen for the import. **Load Mapping** restores them. **Save Mapping** also saves the **Parts separated by** choice, and **Load Mapping** restores it. Otherwise, **Automatic** is preselected.

Open the information icon for an example sorted by planned start. Before importing, the queue is A (20 October), D (28 October, moved forward manually), B (22 October), C (24 October). A new operation N (23 October) goes behind B, giving A, D, B, N, C. D stays second. Existing work keeps its relative order, though inserting work ahead of it can change its position number. This does not keep the queue continuously sorted.

Placement applies to machine queues and hall pools. It includes new work, additional assignments for parallel work, and operations moved to another destination during import. A repeat import that only updates an existing assignment leaves its position unchanged. Placement never changes priorities or dates.

For several operations entering the same queue, **By sorting** inserts them in rule order. **At the start** uses company rule order when company rules exist, otherwise spreadsheet order.

The check summary shows **New operations in the queue:** with your choice. After importing with **By sorting** or **At the start**, a separate line reports the number of operations placed and queues affected, if any work was placed. It also appears alongside conflicts, skipped rows, or warnings. The count includes moved operations. Follow the [import workflow](/en/platform-intro/workflows/order-upload-planner).

## Review the Import's Impact

After mapping and preview, open **What this import will change**. The summary groups new, updated, and existing records by orders, products, customers, operations, and assignments. Existing records are reused; they do not necessarily represent new records created by the import.

Expand the row-by-row details to inspect schedule changes, new operations and assignments, and recalculated durations. Use this view to check the consequences for your current plan before confirming.

<a id="missing-machines" />

### Rows Without a Machine

Step 3 and the check result warn how many rows in your chosen import scope have neither a machine nor a hall pool. **Not mapped:** lists unmatched machine values. These rows can still be imported, but their operations cannot start on the PDA page until planned.

Match the machine values before importing, or assign the operations later under **Planner → Unassigned**. The warning disappears when all included rows have a destination or you choose **Machine assigned**.

## Resolve Scheduling Conflicts

A scheduling conflict appears when the file assigns an operation that is already scheduled elsewhere. Conflicts are grouped under their order and include a reason, such as an assignment that already has recorded production.

| Choice | Effect |
| --- | --- |
| **Move to [new target]** | Apply the assignment from the file. |
| **Keep on [current target]** | Retain the existing assignment instead of applying the file's proposed change. |
| **Keep both** | Keep assignments at both targets for parallel work. |

Some conflicts cannot be resolved in the import review. Follow the indication to resolve those manually in the [Assignment Planner](/en/platform-intro/pages/assignment-planner).

After import, review the outcome summary. It shows which decisions were applied and explains any that could not be applied, for example if production started after your review. Use this result to identify work that still needs attention in the planner.

## Four Stages, Required Fields, and Badges

The current page is **ERP Uploads**, also called ERP Upload Planner in this documentation. Open it through **Planner → ERP Uploads**. Flow: **Upload File → Map Columns → Review & Assign Machines → Review & Save**. Accepted files: **CSV, XLS, XLSX**.

Required mappings are **Order Number, Product, Planned Start, Planned End**. Date/time can be one column or separate columns; a date without time uses midnight or the selected start/end-of-day setting. Rows without schedule information or with start after end are not processed.

- **ALL Units / 1 Unit:** whether planned production time describes the full quantity or a single unit. **1 cycle** is also available when cycles per product is supplied.
- **Industrial minutes:** ordinary minutes = industrial minutes × 0.6.
- Initial priorities apply only to new orders and operations. See the priority settings above for empty cells and invalid values.
- Choose **All rows** to import all rows, or **Machine assigned** to import only rows with a machine assignment.
- **Save Mapping / Load Mapping:** saved per user. Manual machine or hall-pool assignment overrides mapping; **Reset selected rows** removes the manual choices for the selected rows and restores their column mapping.

**Check** is a dry run and saves nothing. **NEW / NEU** means creation, **CHG / GEÄ** means update, **IMPACT** means a calculated planning value is affected. If data changes after Check, run Check again before choosing **Import (n)**.

## Re-import Matching and Protected History

Open **What a re-import changes for existing orders** before confirming a repeat upload.

| Section | What it means for your import |
| --- | --- |
| **How records are matched** | Product name identifies the product; order name identifies the order. A work order combines order and product, an operation combines work order and sequence, and an assignment combines operation and machine. |
| **Updated from the file** | Empty cells keep the current value. Quantities already split across machines stay unchanged and are marked for review. |
| **Never changed** | Existing protected values stay even if the file differs. Production history is never changed. |
| **Only for new records** | Protected values from the file are used only when the order, operation, or product is new. Missing rows delete nothing. |
| **Machine assignments — your decision** | New operations use the machine chosen in the assignment step. For existing assignments on another machine, review whether to move, keep, or keep both. |

Marked cells explain when an existing value will be kept instead of imported. Operations with recorded work stay on their current machine and are still imported. **Keep both** also lets the operation run on the new machine. It does not move the recorded work.

The preview distinguishes **Planned quantity (machine)** from **Planned quantity (work order)**. After import, check the count of updated machine quantities and any warnings. Review marked split quantities in the [Assignment Planner](/en/platform-intro/pages/assignment-planner) before changing the plan.
