## Overview

**Access:** Admin or Page Access `erp_uploads`. [Roles and access](/en/platform-intro/concepts/roles-and-access).

Import spreadsheet-based orders into the Watchmen Platform. Review the source file, match its columns to order fields, and check how the import will affect your existing production plan before confirming it.

Users open it through the protected ERP upload route.

## Access

<Callout kind="info" title="Access details">
- Visibility: Protected
- Primary routes: `/erp-uploads`
</Callout>

## What You Can See

- The selected file's name, row and column count, and a sample of its contents.
- Column mappings and tools for matching external machine names or codes to your machines.
- A preview, time-setting explanations, schedule warnings, and upload progress.
- A summary of proposed changes and scheduling conflicts, followed by the results after import.

## What You Can Do

- Upload a spreadsheet and correct values before importing.
- Map columns to order fields, including order tags, and reuse saved mappings where appropriate.
- Match machine references and, if needed, limit the import to orders that already have a machine assignment.
- Choose the time interpretation, review changes, and decide how to handle scheduling conflicts.
- Confirm the import and check which changes were applied.

## Review and Correct the File

Select **Expand to edit** in the file preview to open the full file view. You can correct individual cells or paste matching groups of values from Excel. The editor shows how many cells you have changed; saved corrections are highlighted in the preview.

Column headings and row counts stay fixed. To change the file structure, correct the source spreadsheet and upload it again. Closing the editor without saving discards unsaved corrections and leaves the original file unchanged.

## Understand Time and Priority Settings

Time fields can use standard or industrial-minute interpretation. Choose the convention that matches your source data. The upload review identifies the affected row and explains when a time value or the **Industrial minutes** setting changes preparation or production time. Check these explanations before confirming the import.

Priority names, numbers, and colors follow the company levels configured in the [Admin Panel](/en/platform-intro/pages/admin-panel). These levels are shared with order management and the Assignment Planner, so imported priorities can be reviewed consistently across the plan.

### Initial Priorities for New Work

Map **Order priority** and **Operation priority** separately. In the column-mapping step, **Initial order priority (new orders)** and **Initial operation priority (new operations)** supply values for new work when a priority cell is empty or no priority column is selected. Leave the initial operation priority empty to use 100.

Operation priorities must be whole numbers of zero or more. Text, fractions, and negative values are marked for correction; the initial value does not replace them. Non-numeric order priorities are also marked. Re-importing never changes the priority of existing orders or operations.

## Review the Import's Impact

After mapping and preview, open **What this import will change**. The summary groups new, updated, and existing records by orders, products, customers, operations, and assignments. Existing records are reused; they do not necessarily represent new records created by the import.

Expand the row-by-row details to inspect schedule changes, new operations and assignments, and recalculated durations. Use this view to check the consequences for your current plan before confirming.

## Resolve Scheduling Conflicts

A scheduling conflict appears when the file assigns an operation that is already scheduled elsewhere. Conflicts are grouped under their order and include a reason, such as an assignment that already has recorded production.

| Choice | Effect |
| --- | --- |
| **Move to [new target]** | Apply the assignment from the file. |
| **Keep on [current target]** | Retain the existing assignment instead of applying the file's proposed change. |
| **Keep both** | Keep assignments at both targets for parallel work. |

Some conflicts cannot be resolved in the import review. Follow the indication to resolve those manually in the [Assignment Planner](/en/platform-intro/pages/assignment-planner).

After import, review the outcome summary. It shows which decisions were applied and explains any that could not be applied, for example if production started after your review. Use this result to identify work that still needs attention in the planner.

## Four Stages, Required Fields, and Badges

The current page is **ERP Uploads**, also called ERP Upload Planner in this documentation. Open it in Planner at `/erp-uploads`. Flow: **Upload File → Map Columns → Assign Machines → Review & Save**. Accepted files: **CSV, XLS, XLSX**.

Required mappings are **Order Number, Product, Planned Start, Planned End**. Date/time can be one column or separate columns; a date without time uses midnight or the selected start/end-of-day setting. Rows without schedule information or with start after end are not processed.

- **ALL Units / 1 Unit:** whether planned production time describes the full quantity or a single unit.
- **Industrial minutes:** ordinary minutes = industrial minutes × 0.6.
- Initial priorities apply only to new orders and operations. See the priority settings above for empty cells and invalid values.
- **Commit scope:** All rows or Machine assigned; the latter imports only rows with a machine assignment.
- **Save Mapping / Load Mapping:** saved per user. Manual machine or hall-pool assignment overrides mapping; **Reset** restores it.

**Check** is a dry run and saves nothing. **NEW / NEU** means creation, **CHG / GEÄ** means update, **IMPACT** means a calculated planning value is affected. If data changes after Check, run Check again before **Save** commits.

## Re-import Matching and Protected History

Open **What a re-import changes for existing orders** before confirming a repeat upload.

| Section | What it means for your import |
| --- | --- |
| **How records are matched** | Product name identifies the product; order name identifies the order. A work order combines order and product, an operation combines work order and sequence, and an assignment combines operation and machine. |
| **Updated from the file** | Empty cells keep the current value. Quantities already split across machines stay unchanged and are marked for review. |
| **Never changed** | Existing protected values stay even if the file differs. Production history is never changed. |
| **Only for new records** | Protected values from the file are used only when the order, operation, or product is new. Missing rows delete nothing. |
| **Machine assignments — your decision** | New operations use the machine chosen in the assignment step. For existing assignments on another machine, review whether to move, keep, or keep both. |

Marked cells explain when an existing value will be kept instead of imported. Operations with recorded work stay on their current machine and are still imported. **Keep both** also lets the operation run on the new machine. It does not move the recorded work.

The preview distinguishes **Planned quantity (machine)** from **Planned quantity (work order)**. After import, check the count of updated machine quantities and any warnings. Review marked split quantities in the [Assignment Planner](/en/platform-intro/pages/assignment-planner) before changing the plan.

**ERP Upload (single machine) Legacy** is an older superseded version; use this current multi-record workflow.
