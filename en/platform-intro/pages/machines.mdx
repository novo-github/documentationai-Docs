## Overview

Give users a fast overview of the available machines and their current production state.

This is the main dashboard route for signed-in users and the default landing page after login for most roles.

## Access

<Callout kind="info" title="Access details">
- Visibility: Protected
- Primary routes: `/machines`
</Callout>

## What You Can See

- Summary counters for machine states such as production, idle, off, and preparation.
- Machine cards with names, hall context, status information, and alerts.
- Sorting and display preferences for which metric is emphasized.

## What You Can Do

- Filter the board by state or contextual tags.
- Sort machines by name or key performance metrics.
- Open a machine to reach its detail page.
- Start machine creation from here if the user has the right access.

Filters and sorting are restored when the user returns to the Machines page.

## Distinguish Machine States with Patterns

The machine status legend explains the colors used for each state. Enable **Accessibility patterns** in the legend to add a visual pattern alongside the existing colors:

| State | Pattern |
| --- | --- |
| Idle | Dots |
| Off | Diagonal lines |

The setting applies wherever machine status is shown, making these states easier to distinguish without relying on color alone.

Select **See how this looks** to compare the same shift timeline with and without patterns, including a simulation of color blindness. Use the preview to check whether the display is easier for you to read.

If a sensor switches off together with its machine, the [Sensor powered by machine setting](/en/platform-intro/pages/machine-configuration#sensors-powered-by-the-machine) lets a missing signal be displayed as **machine off** instead of **unknown**.

## Outcomes and Limits

### Common Outcomes
- Users identify which machines need attention.
- Users jump into a machine detail page for deeper work.

### Limits and Empty States
- Users with no machine access can see an informational empty state instead of machine cards.
- Some creation or admin actions depend on role.
