## Overview

**Access:** Admin only. [Roles and access](/en/platform-intro/concepts/roles-and-access).

Provide one place for shared operational setup that supports the rest of the platform.

Users open it from the main navigation when their role allows it.

## Access

<Callout kind="info" title="Access details">
- Visibility: Protected
- Primary routes: `/admin-panel`
</Callout>

## What You Can See

- Administrative sections for halls, shifts, machine operators, priority levels, and related setup data.
- Creation and edit actions for reusable platform records.

The machine list marks entries of kind **Work center**. These workplaces have no AVA. Admins can create them or change their kind in the [machine configuration](/en/platform-intro/pages/machine-configuration).

## What You Can Do

- Create and maintain halls, shifts, and machine operators.
- Manage downtime reasons and other platform-wide setup items.
- Review and update supporting configuration needed by planning and machine pages.
- Define company priority levels and manage user access to pages and machines.

Admins can search the product table by product name or number.

Admins see the company’s currency symbol in **Energy Price**, both in the price list and when adding or editing prices per kilowatt-hour. If no company currency is set, € is shown. The amounts are unchanged; this does not convert currencies.

## Define Company Priority Levels

Priority levels give your team a shared way to recognize the urgency of work. Each level has a name, number, and color. Match these to your ERP so planners use the same priorities when importing and managing orders.

<Steps>
  <Step title="Open Priority Levels" icon="arrow-right" title-type="p">
    Go to **Admin Panel → Priority Levels**.
  </Step>
  <Step title="Choose a preset or customize the levels" icon="arrow-right" title-type="p">
    Select **Apply preset** to use the priority numbering for **SAP**, **Epicor Kinetic**, or **Infor M3**.

    For your own scheme, define the names, numbers, and colors your company uses. You can add, rename, reorder, recolor, or delete individual levels. Choose **Reset to defaults** if you want to start again with the default levels.
  </Step>
  <Step title="Save the company priorities" icon="arrow-right" title-type="p">
    Save your changes to make the same levels available in [Order Upload](/en/platform-intro/pages/erp-upload-planner), the [Assignment Planner](/en/platform-intro/pages/assignment-planner), and [order management](/en/platform-intro/pages/orders-products).
  </Step>
</Steps>

### How Priorities Are Used

Open the information icons beside the titles to read the section description and explanations for **Which number is more urgent?** and **Queue order and operation priority stay in step**. These explanations now appear there instead of as lines below the titles.

Admins open **Admin Panel → Priority Levels → How priorities are used**, below the levels table.

Under **Which number is more urgent?**, choose:

- **Higher number = more urgent**: the default; 150 comes before 100.
- **Lower number = more urgent**: 1 comes before 5.

This choice controls suggested queue sorting and automatic operation-priority changes. Applying a SAP preset also selects higher numbers first; Epicor and Infor presets select lower numbers first. The preset preview shows the direction. **Reset to defaults** restores higher numbers first as well as the default levels. Your own ascending or descending sorting rules stay as you set them.

**Queue order and operation priority stay in step** is on by default. In the Planner’s queue-position mode, moving a step can change its operation priority. Changing its priority on the card can move it in the queue. Only that operation’s priority changes; order priorities stay unchanged. If you turn this off, dragging only changes queue order and changing priority does not move cards.

Open **How does this work?** for examples using your company’s levels. With the default levels, moving OP30 ahead of OP100 at the top makes it OP150. Moving the second of two OP70 steps to the top of the same queue makes it OP100. If no suitable more urgent level exists, a tie can remain. See [queue and priority behaviour](/en/platform-intro/pages/assignment-planner#queue-order-and-operation-priority).

Each of these settings saves as soon as you change it. Wait for **Setting saved.** If saving fails, the previous choice returns; try again. An amber notice makes it clear when the queue-and-priority setting is off.

In **Improve plan**, **Keep priorities** never changes priorities. **Least delay** and **Fewest changes** can change operation priorities as shown in the proposal while **Queue order and operation priority stay in step** is on. Turning it off prevents priority changes for all searched options. Order priorities never change. See [planning choices](/en/platform-intro/pages/assignment-planner#choose-an-option).

## Manage PDA Access Templates

Admins open **Admin Panel → PDA access templates** to make the PDA page the same on selected machines. Use **New template** to choose fields that stay visible or highlighted, optional fixed sorting and automatic refresh, and allowed actions. The rules apply to everyone on those machines’ Data Acquisition V3 pages, including Admins. Other pages stay unchanged.

Under **Allowed on the PDA page**, switch off **Tick off parts in the parts list** to keep lists readable without allowing ticks or reopening parts on those machines. This does not restrict ticking in the Planner or order details. See [Parts Lists](/en/platform-intro/pages/parts-lists).

The list shows the first three machine names, then **+N more**; hover to see all names. **No machines** marks an empty selection. Each row has **Edit** and **Delete**. Explanations appear behind the information icons beside titles.

Only Admins see and manage this section; each machine can use only one template. Deleting a template returns its machines to each person’s own settings, and the confirmation shows how many: for example, **3 machines will go back to their own settings.**

Turning on **Use a fixed sorting** starts from the company sorting only if a company sorting is saved in the Planner and the template had no fixed sorting before. Otherwise, the starting choices are unchanged. **Use company sorting** appears in the sorting section only when company sorting exists. It shows a tick while the template already uses that sorting. It copies the sort mode and rules; choices for running and on-hold orders and for orders waiting on a previous operation stay unchanged. Without company sorting, the section keeps its usual reset to the built-in default. Saving is available only after a change.

Under **Allowed on the PDA page**, **Reopen completed operations** controls whether **Set on hold** appears in **Recently completed**. It starts on, including in existing templates. You can leave it on while switching **Change the order status** off. The completion choice after **Stop** remains available when the planned quantity is reached.

Under **AI on the PDA page**, **Ask AI in the knowledge base tab** allows questions there for people with AI assistant access. **Fill in tickets with AI** controls AI help when creating a ticket from the PDA page. Both switches start off. Machines without a template have no AI in these places. Saving knowledge remains available with Knowledge Base access. Other pages are unaffected.

See [PDA Access Templates](/en/platform-intro/pages/bde-access-templates) for each setting and its limits, or follow [Make the PDA Page the Same on Several Machines](/en/platform-intro/workflows/bde-access-templates).

## Invite Team Members and Understand Roles

Admins can open **Admin Panel → Users → Invite Team Members**. The button at the top of the Admin Panel opens the same **Invite team members** dialog. Enter the person's email and choose **Role**. Point at or tap the information icon beside it to open **What can each role do?**. The in-app summaries say:

- **Admin** — “Manages the company: users, machines, shifts and settings.”
- **User** — “Works with the pages an admin allows, e.g. machines, orders and reports.”
- **Machine operator** — “Uses only the machine tablet pages for their machines.”

The same short summaries appear below the user table. For access rules, see [roles and access](/en/platform-intro/concepts/roles-and-access). Follow [Invite Users and Manage Permissions](/en/platform-intro/workflows/user-access-management).

## Manage Page and Machine Permissions

Permissions determine which platform pages and machines a user can access. Use them to give each person access to the areas and machines needed for their work.

Open the user record in the Admin Panel and select **Edit Permissions**. Select the pages and machines the user may access, then save. The updated permissions apply to the user's next session.

## Default Priorities and Range Limits

By default, higher numbers mean more urgent work. **Which number is more urgent?** lets Admins reverse this. Defaults: **Low 10, Normal 30, High 70, Critical 100, Highest 150, Extreme 200**. Default colors are green 0–29, blue 30–69, orange 70–99, and red 100+. Companies can set names, values, and colors or apply **SAP Delivery Priority**, **Epicor Kinetic Material Queue Priority**, or **Infor M3 Customer Order Priority** presets.

Custom priority settings allow **0–999**, while the Add Order form states **1–200**. This mismatch needs product confirmation; follow validation in the current form instead of assuming one range applies everywhere. Existing priorities are protected during ERP re-imports.

## Security, AI Data Access, and Account Administration

The **Machine operators** area manages accounts with the Machine operator role. Use **Add machine operator** to create an account or **Update machine operator** when editing one. Confirmation notices for creation, changes, replacement passwords and promotion use your selected language. Follow [manage machine operator accounts](/en/platform-intro/workflows/operator-management).

Access keys for other programs are shown only when you create them. Copy each key while it is visible. **License Key** identifies your company’s licence; it does not provide access for other programs. The AI assistant uses only company data areas you allow in its settings.

Use [Invite Users and Manage Permissions](/en/platform-intro/workflows/user-access-management), [Set Up a Hall Plan Display](/en/platform-intro/workflows/hall-display-setup), and [Manage machine operators](/en/platform-intro/workflows/operator-management) for the tasks.

## AI Assistant Settings

Admins only: open **Admin Panel → A.I. → AI assistant** (previously **AI Assistant Data Access**). The card has **Settings** and **Usage** tabs.

| Level | What it allows |
| --- | --- |
| **Off** | No use of this area. |
| **Read** | Reading only; actions are off. |
| **Read & act** | Reading and selected actions; the person confirms every change. |

Some areas, including **Web search** and **Memory across chats**, are simply on or off. Memory is on by default; you can switch it off for the company, but cannot see anyone’s personal memory. Web search starts off and applies only to the assistant in Watchmen.

Switching off the **Knowledge Base** area prevents people from keeping chat files in the knowledge base. They can still attach and use files in the chat. Keeping also requires the person to have Knowledge Base page access; without both, the keep question, keeping actions and profile preference are hidden. See [chat files](/en/platform-intro/pages/chat-history#keep-chat-files).

**Customize** opens a side panel for one area. Switch individual items on or off, then choose **Apply** at the top. The bar at the bottom of the card shows the number of unsaved changes: choose **Save** to keep them or **Discard** to abandon them.

Under **People**, switch off **AI access** for anyone who should not use the assistant or connected AI apps. **Admins always have access**. Page and machine access still apply. Switch on **AI apps** to let people [connect an outside app with their own account](/en/platform-intro/pages/chat-history#connected-apps).

### Credits and Usage

Answers requested through **Ask AI** in ⓘ help cost no credits for you or your company, even when company credits are used up.

For your company’s monthly AI credits, **When credits run out** offers:

- **Pause** (default): **Auto** and **Deep analysis** wait until next month; only **Fast** still works for a few questions per person per day.
- **Allow overage**: answers continue up to **Extra credits per month**, which you set. Extra credits are billed separately.

Set **Limit per person** and use **Individual limits** under **People** for exceptions. Entered limits must be at least 10 credits; empty means no limit. Save your choices with the other settings.

Open **Admin Panel → A.I. → AI assistant → Usage** to see this month’s company usage, **Last 30 days**, and **By person**. You see interactions and, when AI credits are shown, the credits used. An interaction is one answer, including **Keep going** and failed answers. Failed answers use no credits. If credits are not displayed, you see interactions only. While **Usage** shows **Show only**, credits are shown but nothing is blocked.

When AI credits are shown, **Usage** also gives you a read-only breakdown:

- **Included every month**: the company’s included monthly credits. The amount no longer depends on how many people have AI access.
- Extra monthly credits, with their last month. You receive the full amount each month of their term; unused monthly credits expire at month-end.
- Credit packs, with what is left and each expiry date. A pack is one amount available across its term, not a fresh amount each month.
- **Left this month**: the credits still available this month.

Included credits are used first, then extra monthly credits, then the credit pack that expires first. You cannot add or edit these amounts here. **Need more credits? Write to** points you to [tech@novoai.de](mailto:tech@novoai.de); Admins also see this contact when company credits run out.

## Active Shifts in Machine Lists

In the Admin Panel and company view, **Active shift** identifies machines whose shifts follow machine activity. The assigned shift group is not used while this setting is on. Admins can change the mode and its durations in the [machine configuration](/en/platform-intro/pages/machine-configuration).

## Change a User's Email

Admins can select **Change email** in user management in the Admin Panel or company view for users who are not machine operators. Use this action instead of editing the address in the user form. Enter **New email** and select **Send verification**. The user's current address remains active until they open the link sent to the new address and select **Confirm email change**.

The pending notice shows the address awaiting confirmation. Use **Resend** after the displayed wait or **Cancel change** if the request is no longer needed. Follow [Change Your Email Address](/en/platform-intro/workflows/change-email).

## Manage Shift Breaks

The **Breaks** column follows the shift end. It lists each break's start, end and length on its own line, in the same order as the editor. A shift without breaks shows a dash. A break from 23:30 to 00:15 shows its actual length of 45 minutes.

When creating or editing a shift, type a complete time and leave the box by clicking elsewhere or pressing Tab. You do not need Enter to keep it. A small time selector opens below the box: use − / + with a mouse or the wheel on a touch screen.

If the shift end is earlier than its start, the shift continues into the next day and **Overnight shift · ends the next day** appears automatically. For example, 10:00–09:00 is a valid 23-hour shift. Start and end cannot be the same: **Shift start and end time must be different.** A break within that shift that crosses midnight shows **Break over midnight · ends the next day**. A break ending exactly at 00:00 does not show this break hint.

Each break must fit within the shift and last at most one hour. These messages appear directly below the affected break while you edit and block saving:

- **Break end time must be after break start time.**
- **Break start and end time must stay inside the shift time.**
- **A break can be 1 hour at most.**

Correct all reported problems before saving. Follow [Manage Shift Definitions](/en/platform-intro/workflows/shift-management).

Admins open **Admin Panel → Configure Shifts and Scheduling → Shifts**, then **Break settings** directly left of **Add Shift**. Turn on **Label breaks automatically** and save before choosing a **Downtime reason** for each break in the shift editor. **No downtime reason** leaves that break without an automatic break label.

While the switch is on, the **Breaks** column shows each break's reason after its length. When it is off, these reasons are hidden in the table and the reason choices in the editor are greyed out. Saved choices are kept. The choices are also unavailable while settings load or cannot be loaded.

See [Break Settings](/en/platform-intro/pages/break-settings) for the company-wide options and limits, or follow [set up automatic break labels](/en/platform-intro/workflows/shift-management#automatic-break-labels).

## Manage Downtime Reasons

Only Admins can create, edit, or delete reasons. Open **Admin Panel → Configure Analyzers → Downtime reasons**. The table shows **Code**, **Category**, and **Available on** alongside the reason, description, colour, and level. Search by code or text and filter by category. The availability column shows whether a reason is available everywhere or on a number of machines; its explanation lists their names. **No machines** means the reason is offered nowhere.

The reason form shows name, code, category, description, type and colour on the left, with **Available on machines** on the right. The machine list scrolls separately and shows names without an extra all-reasons tag. Open the information icon beside its title for an explanation of fixed lists. Choose a reason type before saving.

In the reason form, **Code** and **Category** are optional. Codes become uppercase and must be unique within your company. Use up to 20 letters, digits, dots, underscores, slashes, or hyphens, starting with a letter or digit. Choose an existing category or enter one. **Pick colour** opens the colour selector; you can enter a colour value directly or use **Random colour**. New reasons start with a random colour.

Under **Available on machines**, click the checkbox or machine name to choose where machine operators can use this reason. Clicking other parts of the row leaves the selection unchanged. Unticking a machine that currently offers all reasons gives it a fixed list of the other current reasons. Later reasons will no longer appear there automatically. Unticking its last reason leaves that machine with no reasons to choose. You can save a reason with no machines ticked.

Editing a shared reason affects all machines. Select **Delete** in the reason’s row menu and review **Deleting this reason removes it from:**. The notice lists the affected past downtimes, machine reason lists, downtime reason rules and breaks, with counts and example names where available. **This reason is not used anywhere.** appears when there are no uses. While the details load, or if they cannot load, only a general notice appears; deletion remains available.

Deleting the reason keeps past downtime entries but removes their reason without assigning another. It also removes the reason from machine lists, downtime reason rules, defaults and shift breaks. Break times stay unchanged. Future time covered by a removed rule gets the machine's remaining default reason, if any. Reason charts and reports are updated for the affected days. Reports you already received stay as they were. Restricted machine lists stay restricted; deleting their last reason leaves them with none until an Admin changes the selection.

Use [Create and Manage Downtime Reasons](/en/platform-intro/workflows/timeline-reason-creation) for the steps. To set an entire machine's list, use [Machine Configuration](/en/platform-intro/pages/machine-configuration).

## Assign Interactive Guides and Follow Progress

Open **Admin Panel → Interactive guides**. **People** shows assigned completion and last activity; open a person to assign available guides. **Guides** lets you select a guide and assign it to people or **A whole role**, including people who get that role later. Open assignments appear first. A previous guide completion counts as done; assignments have no due dates.

Open a guide to review **Who has it**. Choose the ✕ with the tooltip **Remove assignment** to remove an assignment; role assignments are removed from the guide’s list. You see only your company’s people and guide status. Follow [Assign Guides and Follow Team Progress](/en/platform-intro/workflows/assign-interactive-guides).
