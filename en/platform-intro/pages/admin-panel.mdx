## Overview

**Access:** Admin only. [Roles and access](/en/platform-intro/concepts/roles-and-access).

Provide one place for shared operational setup that supports the rest of the platform.

Users open it from the main navigation when their role allows it.

## Access

<Callout kind="info" title="Access details">
- Visibility: Protected
- Primary routes: `/admin-panel`
</Callout>

## What You Can See

- Administrative sections for halls, shifts, operators, priority levels, and related setup data.
- Creation and edit actions for reusable platform records.

The machine list marks entries of kind **Work center**. These workplaces have no AVA. Administrators can create them or change their kind in the [machine configuration](/en/platform-intro/pages/machine-configuration).

## What You Can Do

- Create and maintain halls, shifts, and operators.
- Manage timeline reasons and other platform-wide setup items.
- Review and update supporting configuration needed by planning and machine pages.
- Define company priority levels and manage user access to pages and machines.

## Define Company Priority Levels

Priority levels give your team a shared way to recognize the urgency of work. Each level has a name, number, and color. Match these to your ERP so planners use the same priorities when importing and managing orders.

<Steps>
  <Step title="Open Priority Levels" icon="arrow-right" title-type="p">
    Go to **Admin Panel → Priority Levels**.
  </Step>
  <Step title="Choose a preset or customize the levels" icon="arrow-right" title-type="p">
    Select **Apply preset** to use the priority numbering for **SAP**, **Epicor Kinetic**, or **Infor M3**.

    For your own scheme, define the names, numbers, and colors your company uses. You can add, rename, reorder, recolor, or delete individual levels. Choose **Reset to defaults** if you want to start again with the default levels.
  </Step>
  <Step title="Save the company priorities" icon="arrow-right" title-type="p">
    Save your changes to make the same levels available in [Order Upload](/en/platform-intro/pages/erp-upload-planner), the [Assignment Planner](/en/platform-intro/pages/assignment-planner), and [order management](/en/platform-intro/pages/orders-products).
  </Step>
</Steps>

### How Priorities Are Used

Open the information icons beside the titles to read the section description and explanations for **Which number is more urgent?** and **Queue order and operation priority stay in step**. These explanations now appear there instead of as lines below the titles.

Administrators open **Admin Panel → Priority Levels → How priorities are used**, below the levels table.

Under **Which number is more urgent?**, choose:

- **Higher number = more urgent**: the default; 150 comes before 100.
- **Lower number = more urgent**: 1 comes before 5.

This choice controls suggested queue sorting and automatic operation-priority changes. Applying a SAP preset also selects higher numbers first; Epicor and Infor presets select lower numbers first. The preset preview shows the direction. **Reset to defaults** restores higher numbers first as well as the default levels. Your own ascending or descending sorting rules stay as you set them.

**Queue order and operation priority stay in step** is on by default. In the Planner’s queue-position mode, moving a step can change its operation priority. Changing its priority on the card can move it in the queue. Only that operation’s priority changes; order priorities stay unchanged. If you turn this off, dragging only changes queue order and changing priority does not move cards.

Open **How does this work?** for examples using your company’s levels. With the default levels, moving OP30 ahead of OP100 at the top makes it OP150. Moving the second of two OP70 steps to the top of the same queue makes it OP100. If no suitable more urgent level exists, a tie can remain. See [queue and priority behaviour](/en/platform-intro/pages/assignment-planner#queue-order-and-operation-priority).

Each of these settings saves as soon as you change it. Wait for **Setting saved.** If saving fails, the previous choice returns; try again. An amber notice makes it clear when the queue-and-priority setting is off.

In **Improve plan**, **Keep priorities** never changes priorities. **Least delay** and **Fewest changes** can change operation priorities as shown in the proposal while **Queue order and operation priority stay in step** is on. Turning it off prevents priority changes for all searched options. Order priorities never change. See [planning choices](/en/platform-intro/pages/assignment-planner#choose-an-option).

## Manage BDE Access Templates

Administrators open **Admin Panel → BDE access templates** to make the BDE page the same on selected machines. Use **New template** to choose fields that stay visible or highlighted, optional fixed sorting and automatic refresh, and allowed actions. The rules apply to everyone on those machines’ Data Acquisition V3 pages, including administrators. Other pages stay unchanged.

The list shows the first three machine names, then **+N more**; hover to see all names. **No machines** marks an empty selection. Each row has **Edit** and **Delete**. Explanations appear behind the information icons beside titles.

Only Admins see and manage this section; each machine can use only one template. Deleting a template returns its machines to each person’s own settings, and the confirmation shows how many: for example, **3 machines will go back to their own settings.**

See [BDE Access Templates](/en/platform-intro/pages/bde-access-templates) for each setting and its limits, or follow [Make the BDE Page the Same on Several Machines](/en/platform-intro/workflows/bde-access-templates).

## Manage Page and Machine Permissions

Permissions determine which platform pages and machines a user can access. Use them to give each person access to the areas and machines needed for their work.

Open the user record in the Admin Panel and select **Edit Permissions**. Select the pages and machines the user may access, then save. The updated permissions apply to the user's next session.

## Default Priorities and Range Limits

By default, higher numbers mean more urgent work. **Which number is more urgent?** lets administrators reverse this. Defaults: **Low 10, Normal 30, High 70, Critical 100, Highest 150, Extreme 200**. Default colors are green 0–29, blue 30–69, orange 70–99, and red 100+. Companies can set names, values, and colors or apply **SAP Delivery Priority**, **Epicor Kinetic Material Queue Priority**, or **Infor M3 Customer Order Priority** presets.

Custom priority settings allow **0–999**, while the Add Order form states **1–200**. This mismatch needs product confirmation; follow validation in the current form instead of assuming one range applies everywhere. Existing priorities are protected during ERP re-imports.

## Security, AI Data Access, and Account Administration

**API-Access Keys** are shown once at creation; copy the key while it is visible. **License Key** is the company licence identifier, not an API key. The Beta AI Assistant can access only data areas enabled here; platform data is not shared with external AI models without admin enablement.

Use [Invite Users and Manage Permissions](/en/platform-intro/workflows/user-access-management), [Set Up a Hall Plan Display](/en/platform-intro/workflows/hall-display-setup), and [Manage Operators](/en/platform-intro/workflows/operator-management) for the tasks.

## Active Shifts in Machine Lists

In the Admin Panel and company view, **Active shift** identifies machines whose shifts follow machine activity. The assigned shift group is not used while this setting is on. Administrators can change the mode and its durations in the [machine configuration](/en/platform-intro/pages/machine-configuration).

## Change a User's Email

Administrators can select **Change email** in user management in the Admin Panel or company view for users who are not operators. Use this action instead of editing the address in the user form. Enter **New email** and select **Send verification**. The user's current address remains active until they open the link sent to the new address and select **Confirm email change**.

The pending notice shows the address awaiting confirmation. Use **Resend** after the displayed wait or **Cancel change** if the request is no longer needed. Follow [Change Your Email Address](/en/platform-intro/workflows/change-email).

## Manage Downtime Reasons

Only administrators can create, edit, or delete reasons. Open the timeline reason area in the Admin Panel. The table shows **Code**, **Category**, and **Available on** alongside the reason, description, colour, and level. Search by code or text and filter by category. The availability column shows whether a reason is available everywhere or on a number of machines; its explanation lists their names.

In the reason form, **Code** and **Category** are optional. Codes become uppercase and must be unique within your company. Use up to 20 letters, digits, dots, underscores, slashes, or hyphens, starting with a letter or digit. Choose an existing category or enter one. **Pick colour** opens the colour selector; you can enter a colour value directly or use **Random colour**. New reasons start with a random colour.

Under **Available on machines**, click the checkbox or machine name to choose where operators can use this reason. Clicking other parts of the row leaves the selection unchanged. Unticking a machine marked **All reasons** gives it a fixed list of the other current reasons. Later reasons will no longer appear there automatically. You cannot leave a machine without a reason this way: give it another reason first or keep this one ticked.

Editing a shared reason affects all machines. Deleting it keeps past downtime entries but removes their reason. If deletion removes a machine's last selected reason, that machine offers all reasons again. Review the deletion notice before proceeding.

Use [Create and Manage Downtime Reasons](/en/platform-intro/workflows/timeline-reason-creation) for the steps. To set an entire machine's list, use [Machine Configuration](/en/platform-intro/pages/machine-configuration).
