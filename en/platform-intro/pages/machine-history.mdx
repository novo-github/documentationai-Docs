## Overview

**Access:** Any role with access to this machine. [Roles and access](/en/platform-intro/concepts/roles-and-access).

Show longer-term machine behavior across many days instead of a single live day.

Users usually reach it from the Machine Details page.

## Access

<Callout kind="info" title="Access details">
- Visibility: Protected
- Primary routes: `/machines/:machineId/machineHistory`
</Callout>

## What You Can See

- Date-range controls.
- KPI averages, trend charts, and downtime reason summaries.
- Historical views that make recurring patterns easier to spot.

**Machine History** now counts time since the last state change for **1W**, **1M**, **3M** or any chosen range, as does the [**Timeline** report](/en/platform-intro/pages/timeline-analysis) over several days. Days spent idle or off now show that time instead of almost nothing; today counts up to now.

When the sensor sends no signal for more than 20 minutes, the last state counts only until the last signal. For a [sensor powered by the machine](/en/platform-intro/pages/machine-configuration), that silent time counts as **Off**.

## What You Can Do

- Change the review period.
- Toggle whether zero-output days count in the analysis.
- Compare how the machine performed over time.

Select the arrow beside the machine name in the breadcrumb path at the top of the page to switch machines. The name itself still opens the machine page. The list shows your machines grouped by hall, with the current machine checked. With more than 8 machines, use **Search machines…**; ↑/↓ and Enter choose, and Esc closes.

Switching keeps the date range and the **1W** / **1M** / **3M** choice, and selects the shift with the same name even if the shifts are listed in a different order. If the other machine has no shift with that name, **All Shifts** is selected. Browser Back returns to the previous machine with its previous range. Follow [review machine history](/en/platform-intro/workflows/machine-history-review).

## Review Worked Orders

The **Orders** section shows work recorded on this machine during the selected period. The chart opens with the whole period in view. Its upper bars show worked stretches: **Production** uses a white bar and **Preparation** a white bar with a blue border. An operation can have several bars. The row underneath shows machine states on the same time axis. The legend sits above the chart.

Use **Zoom in**, **Zoom out**, or hold Ctrl and scroll to zoom. Scroll sideways or drag empty chart space to move through time. **Whole period** returns to the full view. Zooming out and fitting are unavailable when the whole period already fits.

The worked-time total covers the displayed period. The order count counts each order once, even when it has several operations. For longer selections, the orders chart and its state row show only the last 3 months. The notice reads **Orders are shown for the last 3 months of the selected period.**

<a id="select-a-step-and-follow-its-order" />

### Select an Operation and Follow Its Order

A part passed on shows **Handed over** in the list, card details, and selected operation. Its grey badge shows where the rest went and how many good parts were made here. Incoming work shows where it came from. Recorded work stays in this machine's history; the label does not mean the whole operation is finished. See [handover details](/en/platform-intro/pages/order-detail#handed-over-work).

Nothing is selected when you open the section or change the period. Click a bar to highlight that operation's stretches and find it in the list below. You can also click a list row. The list shows running work first, then recent work, grouped by day.

The details panel appears beside the list on wide screens and below it on smaller screens. It shows the selected operation's status, actual times, planned window, and quantities. **Operations of this order** (previously **Steps of this order**) shows the route, including previous and next operations. Operations marked **On another machine** are visible but cannot be selected here. Under **Order**, check **Delivery date**, status, and how many operations are done.

Choose **Open order** to open the full order in a new tab if you have access. Selecting a row only selects the operation; it does not open the order. Close the panel or click empty chart space to clear the selection. Reviewing history changes no intervals or plans.

<a id="compare-booked-time-with-machine-states" />

### Compare Time in Intervals with Machine States

**Time in intervals** splits the operation's recorded time into **Preparation** and **Production**. **Machine states** shows what the machine actually did during those intervals, including idle, off, or unknown time. Use each section's information icon for its explanation. For example, a production interval can include time when the machine was idle.

The operation's details cover all its recorded work on this machine, including work outside the selected period. Its times, produced quantity, and analysis totals can therefore exceed what the chart shows. Hover over a bar to see that stretch's **Type**, **Start**, **End**, **Duration**, and machine states first, followed by the operation's details. The information icon at the end of a list row shows the operation without selecting it.

Hover over the state row to read the state, its times, duration, and any recorded reason. **Accessibility patterns** in your profile also applies to this row and its legend: dots for idle and diagonal lines for off.

### Empty Orders or Missing States

Without recorded work, the section keeps its space and shows **No orders were worked on this machine in this period.** in a centred message instead of a chart. This does not prove the machine was off; it means no order work was recorded in that period.

Missing state information is separate: the state row can show **No machine state data in this period.** and the selected operation can show **No machine state data for this operation.** Follow [Review Machine History](/en/platform-intro/workflows/machine-history-review).

## All Day or Planned Shift Time?

For machines using scheduled shifts, **All Day** uses 24 hours and **Planned** uses scheduled shift time. Match this mode, the date range, and the zero-output-day choice when comparing averages. Work centers have no sensor-based analytics.

**AVL** means Availability; **PRO** means Performance. Watchmen's time-based definitions differ from textbook OEE. Use [calculations](/en/platform-intro/concepts/calculations#oee) to interpret them before comparing periods.

## Understand Active Shifts

**Active shift** identifies a machine whose shifts follow machine activity. A shift starts at idle, production, or preparation and ends according to the machine's shift settings. Its assigned shift group is not used. See [Machine Configuration](/en/platform-intro/pages/machine-configuration).

**Waiting for the next active shift** or **waiting for machine start** means the next shift has not started yet. It starts automatically when the machine begins idle, production, or preparation. Until then, planned shifts from the assigned shift group are shown. This display does not switch off active shifts.

Select the shifts you want to review; the charts use the selected shifts. Open the shift details to check their times. Choose **Whole day** to review the full day. Shift energy totals follow the company's local shift times. Follow [Review Machine History](/en/platform-intro/workflows/machine-history-review).

## Read Automatically Labelled Breaks

If an administrator enables [automatic break labels](/en/platform-intro/pages/break-settings), finished idle or off downtime can receive the reason of a scheduled shift break. A person's choice takes priority. Earlier completed downtime is not relabelled when the setting is turned on.

With **Label only the break (recommended)**, a longer downtime can appear as several parts: the break with its tolerance, plus the time before or after it. Each part counts as one downtime in counts and averages by reason. The remaining parts use the rules for their own length. Total time in each machine state stays the same. With **Label the whole downtime**, a long breakdown can appear entirely under the break's reason.

## Read Downtime Reason Codes

Downtime chart labels include a reason's code when one is set. Short labels may be cut off; hover over a bar or pie slice to read the full name, code, and category. Categories help identify reasons; the charts still group by reason.

See [downtime reason settings](/en/platform-intro/pages/admin-panel) for how administrators maintain these labels.
