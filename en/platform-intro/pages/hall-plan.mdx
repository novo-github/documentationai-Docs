## Overview

**Access:** Admin or User; never Operator. Kiosk displays use an API key without login. Display administration is admin-only. [Roles and access](/en/platform-intro/concepts/roles-and-access).

Review production across a hall on your own screen or on a shared production-floor display. A kiosk is a simplified view for a screen that runs without someone continuously operating it.

Users open a hall-specific route, often from a shared link or display device.

## Access

<Callout kind="info" title="Access details">
- Visibility: Hall-specific displays can be public; display configuration and device monitoring are administrative actions
- Primary routes: `/hallPlan/:id`
</Callout>

## What You Can See

- Machines, current states, active orders, and produced pieces across the hall.
- OEE, availability, performance, and machine-time metrics.
- Live information alongside previous-shift information.
- A compact, paginated machine view for large halls.
- Display connectivity and last-seen information for managed devices.

## What You Can Do

- Review the hall at a glance.
- Select which production metrics appear.
- Choose the Hall Plan display version and zoom level.
- Configure kiosk language, machine sorting, visible metrics, refresh frequency, and page rotation.
- Choose which production statistics appear in kiosk navigation.
- Monitor live and offline Hall Plan devices.

## Understand the Page

### Choose the Information on Your Display

In the Hall Plan display settings, choose the view version, zoom, visible production metrics, and machine sorting. Select a language and refresh frequency that suit the people using the display. Page rotation lets an unattended screen move through the configured views, while the kiosk navigation settings determine which production statistics are available.

Review current machine states, active orders, and produced pieces together with OEE, availability, performance, and machine times. Compare live information with the previous shift and use planned and actual setup, production, and cycle times to understand deviations. Company branding helps identify the shared hall display.

### Show Product Information

Order cards show **Handed over** for the part finished on a machine when the rest continues elsewhere. A compact grey badge can show only an icon and numbers, such as 40/100. Hover over it for the destination or source and quantities. The Hall Plan shows handovers but cannot make them. Use [Data Acquisition](/en/platform-intro/workflows/data-acquisition#back-to-pool) or [Assignment Planner](/en/platform-intro/workflows/assignment-planner#hand-over-work).

In the display settings, choose **Product information → On**. When the active order's product has an image, its product image, product name, and operation sequence (#) appear next to the machine image. Order names and positions help you identify the work.

Choose **Off** to hide this product display. When it is off, or the product has no image, the operation sequence appears in the order card instead. Order and operation priority always appear in the order card. Follow [Set Up a Hall Plan Display](/en/platform-intro/workflows/hall-display-setup).

### Read Active Shifts and State Patterns

**Active shift** means the machine's shifts start and end with machine activity. **running** identifies an active shift that is still in progress. Use the shift information when comparing current work with the previous shift; the assigned shift group is not used for these machines. See [active shift settings](/en/platform-intro/pages/machine-configuration).

Click the state-pattern icon to see examples of how machine states look with patterns.

### Alternate Key Figures and Shift Orders

Administrators can show **Active order** in the display’s column selection. **Key figures / orders switch** then sets how long each machine shows key figures and then orders worked during the shift. It is available only while **Active order** is visible.

The switch time cannot exceed half the page-switch time. If you shorten the page-switch time, the order switch is limited to fit. Both views can then appear before the next page. **No orders worked in this shift** means no work on orders is shown for that shift.

Order and operation priorities use the company’s priority levels on shared kiosk displays too. Follow [Set Up a Hall Plan Display](/en/platform-intro/workflows/hall-display-setup).

### Check Display Connectivity

Administrators can review whether a managed display is live or offline and when it last reported activity. These indicators describe the display's connection, not the production state of a machine. If a screen appears out of date, check its connectivity and last-seen information before interpreting the displayed production values.

### Read Work Centers and Waiting Shifts

Work centers show running orders instead of machine KPIs. They have no AVA and do not contribute to machine-state counters. See [Work Centers](/en/platform-intro/pages/work-centers).

**Waiting for the next active shift** or **waiting for machine start** means the next shift has not started yet. It starts automatically when the machine begins idle, production, or preparation. Until then, planned shifts from the assigned shift group are shown. This display does not switch off active shifts.

## OEE, AVL, PRO, and PCS on Wall Displays

These captions stay the same in English and German: **OEE** is Overall Equipment Effectiveness; **AVL** is Availability; **PRO** is Performance, not Production; **PCS** is Pieces. A ring's center caption identifies the displayed metric. [Calculations](/en/platform-intro/concepts/calculations#oee) explains the platform-specific definitions.

## Kiosk Timing and Network Details

A kiosk opens without a user login. **Data refresh** sets update timing. **Page switch** cannot be slower than data refresh. **Key figures / orders switch** is at most half the page-switch time. **Page zoom** applies to the display monitor.

**Displays** in Admin Panel → Halls lists registered monitors, last-seen time, **Wi-Fi / WLAN**, **Local IP / Lokale IP**, and **MAC**. A display not reporting for 24 hours is shown as not seen. Use [Set Up a Hall Plan Display](/en/platform-intro/workflows/hall-display-setup).

## Outcomes and Limits

### Common Outcomes
- Users understand the current hall-wide production picture quickly.
- Unattended displays rotate through the configured production view and load application updates automatically.

### Limits and Empty States
- The page depends on a valid hall route and visible machine data.
- Device status depends on the display reporting its connectivity and last-seen information.
