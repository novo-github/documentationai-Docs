<a id="operation-priority" />

## Can I give one operation a different priority from its order?

Yes. In Assignment Planner, select the dashed **OP** chip to change **Operation priority**. The **P** chip changes **Order priority** independently. Follow [Plan Machine Assignments](/en/platform-intro/workflows/assignment-planner).

You can also choose the operation priority while creating an order or editing an operation. The dashed **OP** indicator beside its name shows the result. Follow [Create a Production Order](/en/platform-intro/workflows/create-production-order).

<a id="missing-work" />

## Why did my work disappear after I set a priority filter?

With **Order priority** and **Operation priority** both selected, work must match both. Filters affect unassigned operations and machine columns. Also check any order, product, or customer filter chip above the board. The information icon opens **Assignment Planner Guide**; see the [planner page](/en/platform-intro/pages/assignment-planner).

<a id="planning-dates" />

## Which dates should I use to sort the steps of an order?

Use **Operation Planned Start** or **Operation Planned End** for individual steps. **Order Planned Start** and **Order Planned End** apply to the whole order and keep its steps together when sorting. Follow the [sorting steps](/en/platform-intro/workflows/assignment-planner).

<a id="grouping" />

## How can I see an order’s work by machine?

On the order page, choose **Group by → Machine**. Choose **Operation** to return to a view by production step. See [Order Detail](/en/platform-intro/pages/order-detail).

<a id="actual-dates" />

## Why do planned dates change when I expand an order?

The grouped row shows the whole order’s planned window. Expanded rows show each assignment’s own window. The planned/actual choice beside the date pickers decides whether the date filter searches scheduled or recorded work. See [Orders & Products](/en/platform-intro/pages/orders-products).

<a id="import-priority" />

## Why didn’t a repeat import change the priority?

Existing orders and operations always keep their priority. **Initial order priority (new orders)** and **Initial operation priority (new operations)** apply only to new work with empty priority cells or no selected priority column. An empty initial operation priority uses 100. See the [import settings](/en/platform-intro/pages/erp-upload-planner).

<a id="invalid-priority" />

## Why is my operation priority marked even though I set an initial value?

The initial value fills empty priorities only. Text, fractions, and negative operation priorities are marked for correction. Enter a whole number of zero or more, then review the import again. Follow the [import workflow](/en/platform-intro/workflows/order-upload-planner).

<a id="recorded-work" />

## Why does an imported operation stay on its old machine?

Recorded work prevents it from moving, but the operation is still imported. Choose **Keep both** if it should also run on the new machine. Production history stays unchanged. See [re-import protection](/en/platform-intro/pages/erp-upload-planner).

<a id="split-quantity" />

## Why does the import ask me to review machine quantities?

Quantities already split across machines stay unchanged and are marked for review. Compare **Planned quantity (machine)** with **Planned quantity (work order)**, then inspect the affected work in Assignment Planner. Follow the [import workflow](/en/platform-intro/workflows/order-upload-planner).

<a id="work-center-planning" />

## Can I plan work at a station without a sensor?

Yes. An administrator can create a **Work center**. Select it as the destination for an order or assignment, then review **Orders today** and **Up next** under **Machines → Work centers**. Follow [Add a Machine or Work Center](/en/platform-intro/workflows/add-machine) and [Plan Machine Assignments](/en/platform-intro/workflows/assignment-planner).

<a id="work-center-switch" />

## What happens to the sensor when I change a machine to a work center?

The change removes its AVA assignments and stops all KPI calculation. Only administrators can change the kind. To collect readings again, save it as **Machine** and assign an AVA in the AVA tab. Follow [Configure a Machine](/en/platform-intro/workflows/machine-configuration).

<a id="work-center-kpis" />

## Why does my work center have no OEE or machine status?

A **Work center** has no AVA. It shows today’s worked orders and the waiting queue instead of sensor KPIs and is excluded from state counters and analytics. Missing KPIs do not mean zero performance. See [Work Centers](/en/platform-intro/pages/work-centers).

<a id="planner-view" />

## How do I switch from planning cards to the timeline?

Use the view switch in Assignment Planner or Assignment Gantt. Review dates in the timeline, then return to the planner to change assignments. Follow [Plan Machine Assignments](/en/platform-intro/workflows/assignment-planner).

<a id="forecast-meaning" />

## What does the Forecaster tell me?

It shows when work is expected to start and finish using current progress, queues, shifts, and earlier steps. Your planned dates stay unchanged until you save a planning change. Open **Forecaster** on Orders & Products, the order page, or Assignment Gantt. See the [Forecaster guide](/en/platform-intro/pages/assignment-gantt).

<a id="forecast-filters" />

## Why are late orders outside my date range still shown?

The Forecaster’s late-order filters pause date range and status filters. Order, product, customer, and machine filters still apply. Remove the Forecaster filter to use dates and status again. See [Orders & Products](/en/platform-intro/pages/orders-products).

<a id="forecast-counts" />

## Why do Orders and the Gantt show different warning counts?

Orders & Products counts open orders late for delivery across the company. Assignment Gantt includes other warnings on selected machines, from last week to three weeks ahead and any week you have scrolled to. See [Assignment Gantt](/en/platform-intro/pages/assignment-gantt).

<a id="unplanned-orders" />

## How do I find orders that are missing from every planning board?

Open **Orders & Products → Forecaster → Not planned at all → Show list**. These orders have a delivery date but no operation on a machine or in a hall pool. Open an order to **Assign operations**. A step also needs a planned start before it counts as planned. Follow the [planning workflow](/en/platform-intro/workflows/assignment-planner).

<a id="forecast-risk" />

## What does “at risk” mean, and can the expected finish be too early?

**at risk** (previously **tight**) means the work barely fits or an earlier step is not planned. Missing steps, planned durations, or shift plans can make the expected finish too early. Review these before relying on the date. See the [Forecaster explanation](/en/platform-intro/pages/assignment-gantt).

<a id="held-work" />

## Why does a long-held step still delay the work behind it?

The forecast assumes the paused step continues in its queue position, so later work still waits. Passing **Hold limit (working hours)** only adds **On hold for a long time**; it does not free the machine. Admins set the limit in Assignment Gantt under **View options → Planning** and choose **Save**. Only machine working time counts; without planned shifts, 24 hours count as the full limit. See [planning settings](/en/platform-intro/pages/assignment-gantt#planning-settings).

<a id="save-plan" />

## Does trying a different ordering change my plan?

No. Comparing options in **Improve plan** and using **Show on board** only previews changes. **Save as plan** saves the displayed queue and planned-date changes, plus any operation-priority changes shown for the searched sequence. Delivery dates stay unchanged. **Undo** restores saved changes. Follow [Compare and Save a Plan](/en/platform-intro/workflows/assignment-planner#compare-and-save-a-plan).

<a id="move-undo" />

## Why can I not move an assignment or undo its move?

Running, on-hold, and finished assignments cannot use the Gantt move controls. Recorded work prevents changing the machine. Automatic ordering by delivery date prevents manual queue reordering. If the queue changed after a move, automatic undo is unavailable; review it and move the assignment back by hand. See [move limits](/en/platform-intro/pages/assignment-gantt).

<a id="parallel-jobs" />

## How do I tell the forecast that a machine runs several jobs at once?

An administrator sets **Planning → Jobs in parallel** in the machine’s basic information. Enter a whole number from 1 to 100 that matches actual capacity, then save. Follow [Configure a Machine](/en/platform-intro/workflows/machine-configuration).

<a id="forecast-rule" />

## Who can change what the Forecaster runs next?

Only Admins choose the plant’s ordering under **View options → Planning** and select **Save**. Everyone else who can open Gantt can read these settings but cannot edit them; they see **Ask an admin to change these.** With planning access, you can compare alternatives in **Improve plan** without changing the company rule. Follow [Set the Plant’s Forecast Rule](/en/platform-intro/workflows/assignment-planner#set-the-plants-forecast-rule).

<a id="forecast-help" />

## Where can I open the Forecaster explanation?

Click the information icon beside **Forecaster** on Orders & Products, the order page, or Assignment Gantt. In Assignment Planner, open **Forecaster check → How does the Forecaster work?**. The help explains the colours, expected times, and why a finish may be too early. Opening it changes nothing in your plan. See the [Forecaster guide](/en/platform-intro/pages/assignment-gantt).

<a id="queue-date" />

## Why does Up next show work for another day?

**Up next** is the whole machine queue, independent of the selected date. **Worked** follows the selected day. Waiting steps show planned times and keep their queue numbers when filtered. Follow [Monitor a Machine Live](/en/platform-intro/workflows/live-machine-monitoring).

<a id="queue-limit" />

## Why does the card show fewer waiting steps than the total?

Machine and work center cards show the first 10 waiting steps. The total counts the entire waiting queue. Running steps appear in **Orders today**. Open the [machine page](/en/platform-intro/pages/machine-details) for the whole queue, with running steps first.

<a id="priority-default" />

## Why does a new operation have priority 100?

New operations and operations without a saved priority start at 100. Its name and colour depend on your company’s priority levels; with the default levels, 100 is **Critical**. Choose another company level in the order or operation form. A saved value outside those levels remains selectable. See [Order Detail](/en/platform-intro/pages/order-detail).

<a id="planner-machines" />

## How many machines can I plan at once?

You can select up to 25 machines in Assignment Planner or Assignment Gantt. Planner hall pools do not count toward that limit. Gantt has no pool columns. See [Assignment Planner](/en/platform-intro/pages/assignment-planner).

<a id="pool-placement" />

## How do I keep hall pools visible while I scroll through machines?

On a wide screen, open **Hall pools → Where to show them → Beside the list**, then tick halls under **Which pools to show**. Your choice is saved for your account. **In the board** returns pools to the machine layout. Follow [Plan Machine Assignments](/en/platform-intro/workflows/assignment-planner).

<a id="collapsed-pool" />

## Can I drop work into a collapsed pool?

Yes. For moves without a dialog, dropping onto the narrow strip places work at the end of the pool, including cards not yet shown. If your search covers the pool, close it first so the work lands at the very end. Otherwise, the drop can land among the cards. **Unassigned** does not filter pools. Click the strip or use **Expand pool** to see its cards again. See [hall-pool controls](/en/platform-intro/pages/assignment-planner).

Started, stopped work opens a handover dialog. After confirmation, its remainder goes to the top of the pool, including when the pool is collapsed. Follow [hand over work](/en/platform-intro/workflows/assignment-planner#hand-over-work).

<a id="planner-search" />

## Where has the Planner search box gone?

Press Ctrl+F (⌘F on a Mac) or use the search icon in **Filter & Sort**. Search for an order, product, or customer and choose an area under **Search in**. Esc or × closes and clears search. The icon remains available when the unassigned list is hidden. Follow the [search steps](/en/platform-intro/workflows/assignment-planner).

<a id="search-area" />

## Why does my search leave cards on machines or in pools?

Search starts with **Unassigned**, which only filters the unassigned list. Choose **Search in → Everything** to filter the list, pools, and machines together. **Machines** searches work on machines, not machine names. Your choice is remembered; a link with a search uses **Everything** for that visit without replacing it. See [search choices](/en/platform-intro/pages/assignment-planner).

<a id="planner-cards" />

## Why does my Planner queue show only 40 cards?

Queues initially show 40 matching cards. Use **Show 40 more**, or the smaller remaining number, for the next cards. The count and summary include every card in the queue, also the ones not shown yet. Pools load up to 500 assignments and machine queues up to 100. See [queue display limits](/en/platform-intro/pages/assignment-planner).

<a id="gantt-selection" />

## Why does the Gantt stay the same while I select machines?

The timeline applies your choices when you close the machine selection menu. You can select several machines or a hall group before closing it, up to 25 machines. See [Assignment Gantt](/en/platform-intro/pages/assignment-gantt).

<a id="large-pool" />

## Why was my operation added but not put in the position I chose?

A hall pool loads up to 500 assignments; a machine queue loads up to 100. With **Queue Position** on, dropping an unassigned operation into a large queue adds the work but does not save its chosen position. This affects hall pools with more than 500 active assignments and machine queues with more than 100. The Planner shows **Could not persist queue reorder. Local changes were rolled back.** and reloads the queue. Check the queue before trying again. Reordering work already in a large pool is still saved. See [Planner limits](/en/platform-intro/pages/assignment-planner).

<a id="waiting-sort" />

## How do I move orders that cannot start to the bottom?

In Data Acquisition V3, open **Card Display Settings → Sort Order**. With **Sort by Queue Position** off, click **Add sort rule**, select **Waiting on a previous operation** and choose **At the bottom**. This rule comes before priority or date, but after **Running and on-hold orders** if you add that rule. **At the top** lets you review waiting orders first. Select **Save** to apply your choice. Follow [Configure the Data Acquisition V3 Display](/en/platform-intro/workflows/data-acquisition#configure-the-data-acquisition-v3-display).

<a id="waiting-queue" />

## Can I put waiting orders last and keep the planned queue order?

Yes. With **Sort by Queue Position** on in Data Acquisition V3, choose **Orders waiting on a previous operation → At the bottom**. Waiting work appears after other orders. To bring running and on-hold work first as well, choose **Running and on-hold orders → At the top**. Select **Save**. The queue order stays the same within each group. **Keep in place** restores the usual queue display. Your choice is saved for your account and applies to the machine list and **Pool**. These options are not offered in Assignment Planner. See [Data Acquisition](/en/platform-intro/pages/data-acquisition).

<a id="waiting-refresh" />

## Why is my order still marked as waiting after the previous step finished?

Check whether another step with a lower number in the same work order is still unfinished. A step without an assignment also counts as unfinished. Earlier steps must be completed or cancelled. Once none remains unfinished, the next refresh moves the order into the group that can start. See [waiting orders in Data Acquisition](/en/platform-intro/pages/data-acquisition).

<a id="priority-queue" />

## How do I put one order before another without raising its operation priority?

Ask an administrator to turn off **Admin Panel → Priority Levels → Queue order and operation priority stay in step**. Then enable **Sort by Queue Position** and drag the card; only its place changes. While the setting is on, use **Undo** in a drag’s priority notice to restore the priority and keep the new place. Applying **Re-sort** does not change priorities either. See [queue and priority behaviour](/en/platform-intro/pages/assignment-planner#queue-order-and-operation-priority).

<a id="queue-sort-access" />

## Where is the button to sort by priority and date?

It is now **Re-sort**, on the last line of a machine or hall-pool header. In Assignment Planner, enable **Sort by Queue Position**. You need planning access and access to the machine. Gantt also offers it on each machine row. It now lets you choose a priority or date and keep selected operations in place. See [Re-sort a Queue](/en/platform-intro/pages/assignment-planner#re-sort-a-queue).

<a id="queue-sort-undo" />

## Can I undo a queue sort, and why did the proposal change?

After applying, use **Undo** in the **New sequence applied** confirmation. If someone changes the queue while you review a proposal, it reloads for you to check again. If loading fails, retry before applying. If undo fails, the queue reloads. In Gantt, the message **The old sequence could not be put back. The board now shows the current plan.** appears first when **Undo** cannot be saved. Check the current order before adjusting it. Follow the [queue sorting steps](/en/platform-intro/workflows/assignment-planner#sort-a-queue-by-priority-and-date).

<a id="queue-numbers" />

## Why have the numbers on my Planner cards disappeared?

Numbers show **Place in this queue** only in queue-position mode. Clear priority, operation priority and tag filters, restore the usual status selection, and clear search in the affected area. Numbers count active work and continue when you reveal more cards. Completed and cancelled cards have no number. Data Acquisition cards do not show them. See [queue position numbers](/en/platform-intro/pages/assignment-planner#read-queue-position-numbers).

<a id="company-sorting" />

## Who can set the sorting everyone starts with?

Administrators can set the mode, rules, and **Moves** in Assignment Planner under **Filter & Sort**, then choose **Save as company default**. People without personal sorting start with it; existing personal choices take precedence. Data Acquisition uses the mode and shared rules, with separate choices for running and waiting work. Follow [Save or Use Company Sorting](/en/platform-intro/workflows/assignment-planner#save-or-use-company-sorting).

<a id="sorting-default-updates" />

## Why hasn’t my sorting changed with the company default?

Your own saved sorting takes precedence. A reset also saves a personal copy of the current company choices; it does not follow later changes. Reset again to use the newer choices. In Data Acquisition, saving unrelated display changes keeps you following the default if you have no personal sorting. See [company sorting](/en/platform-intro/pages/assignment-planner#save-or-use-company-sorting).

<a id="running-sort" />

## Why are running orders no longer at the top in Data Acquisition?

Previously, running and on-hold orders stayed on top automatically with **Sort by Queue Position** on. In Data Acquisition V3, they now keep their queue position by default with **Keep in place**. Open **Card Display Settings → Sort Order** and choose **Running and on-hold orders → At the top** to show them first. In Assignment Planner, queue-position mode keeps running and on-hold cards at the positions you set by dragging. With queue sorting off, add **Running and on-hold orders** as a rule and choose **At the top** or **At the bottom**. It comes before the waiting-order rule. Select **Save**. Follow the [display setup steps](/en/platform-intro/workflows/data-acquisition#configure-the-data-acquisition-v3-display).

<a id="pda-sorting-reset" />

## How do I restore company sorting on the PDA page?

In Data Acquisition V3, open **Card Display Settings → Sort Order → Reset to company sorting**, then **Save**. A tick means the mode and rules already match, so the button is unavailable. Reset keeps the queue-mode choices for running and waiting orders but replaces sort rules; add any special running- or waiting-order rules again. Without a company default, the icon labelled **Reset to default (no company default set yet)** restores standard choices. See [Data Acquisition](/en/platform-intro/pages/data-acquisition#use-the-company-sorting-default).

If **Sorting is set by the template** appears, you cannot reset sorting here. Ask an administrator to review the [machine template](/en/platform-intro/pages/bde-access-templates).

<a id="back-to-pool" />

## How do I return work when my machine cannot finish it?

In Data Acquisition V3, select the step and choose **Back to pool**. Running work first opens the normal stop dialog for quantities, then any **PDA Assist** time choice. Confirm the remaining quantity and optional reason in the return dialog. Work goes to your machine’s own hall pool; recorded times and good parts stay on the original machine. Follow [return work to the pool](/en/platform-intro/workflows/data-acquisition#back-to-pool).

The machine’s template must allow **Send orders back to the pool**. If the action is missing, ask an administrator to review the [template](/en/platform-intro/pages/bde-access-templates).

<a id="create-after-selection" />

## Where has the Create button gone?

In Data Acquisition V3, **Create** becomes **Back to pool** while a step is selected. Tap the selected card again to clear the selection and bring **Create** back. See [Data Acquisition](/en/platform-intro/pages/data-acquisition).

A machine template can also hide order creation or returning work. If clearing the selection does not bring the action back, ask an administrator to check [allowed actions](/en/platform-intro/pages/bde-access-templates#allowed-actions).

<a id="return-disabled" />

## Why is Back to pool unavailable?

Finished and cancelled steps stay on the machine. A machine without a hall has no pool; ask your planner to check its hall. Hover over the unavailable button to read the reason. A running step can use **Back to pool**, but you must stop it in the dialog first. See [return requirements](/en/platform-intro/workflows/data-acquisition#back-to-pool).

<a id="handover-machine" />

## Can I send the remaining work straight to another machine?

Administrators and users with access to the Orders page can drag a started, stopped card in Assignment Planner onto another machine they can access. Every user also needs access to the step’s current machine. Other users can only return work to the pool of its current machine’s hall, in Assignment Planner or Data Acquisition. Review **Quantity left**, add **Reason (optional)**, and confirm **Move**. The remainder goes to the top of that machine’s queue. Administrators and users with access to the Orders page can also choose any hall pool. Data Acquisition only returns work to the current machine’s own hall pool. Follow [hand over work](/en/platform-intro/workflows/assignment-planner#hand-over-work).

<a id="handover-quantity" />

## Why is the quantity left higher than I expected?

**Quantity left** subtracts only good parts from the planned quantity. Scrap must be made again. For example, 40 good parts out of 100 leave 60, even if you also recorded scrap. Change the quantity if more parts are needed, or leave it empty if unknown. If nothing is left, finish the step unless you need more parts. See [quantity rules](/en/platform-intro/pages/data-acquisition).

<a id="handover-status" />

## Does Handed over mean the whole step is finished?

No. **Handed over** marks the finished part on the original machine. The rest remains open, and later steps can still be waiting. **Partly done:** shows quantities and where the remainder is. In Data Acquisition, choose the third view tab with the history icon, **Time Window + All Statuses**. It shows all steps in the chosen date window, including completed and cancelled ones. **All Open** and **Time Window + Open** hide the handed-over part. On the order, hover over **Handed over** for each affected step. See [handover details](/en/platform-intro/pages/order-detail#handed-over-work).

<a id="handover-undo" />

## Can I undo a handover?

Administrators and users with access to the Orders page can undo a handover of started work manually, but only while the remainder has not started and is still waiting in a pool or queue. If it has already run on the other machine, you cannot undo it. Do not delete that part: deleting it also deletes its recorded times.

First, note the original quantity: the second number in **Partly done:**, such as 100 in “40 of 100”. You can also find it by hovering over the order’s **Handed over** badge. After deleting the new part, the line changes to **Done on** and no longer shows the original quantity. If no “of …” number appears because the planned quantity was unknown, there is no original quantity to restore.

1. Delete the new part, identified by **From … already done**. On the order detail page, select the red **Delete** button (trash icon) in its assignment row, then confirm **Delete**. Alternatively, drag its card in Assignment Planner onto **Unassigned Operations**. This removes it immediately, without confirmation.
2. On the [order detail page](/en/platform-intro/pages/order-detail#handed-over-work), find the first machine’s part marked **Handed over**. Select **Edit** (pencil icon). In **Edit Assignment**, choose **Hold**, restore **Planned Qty** to the original quantity if known, and select **Save**.

The first part is back in its machine’s queue on hold, with its recorded times and good parts. Its **Handed over** label, the order’s **Handed over** badge and the step’s **Partly done:** line disappear. For example: 40 of 100 made on DMU 50, with 60 still waiting in the Hall 2 pool—delete the 60-part assignment, then set the DMU 50 part to **Hold** with **Planned Qty** of 100.

<a id="handover-changed" />

## Why do I see “This operation was changed in the meantime”?

The step changed while you were reviewing it. The dialog closes. Data Acquisition refreshes the list; Assignment Planner refreshes both queues. You then see the notice **This operation was changed in the meantime. The list has been refreshed.** Check the current step before trying again. Review the machine, running state, and quantities instead of repeating the old choice. See [return work to the pool](/en/platform-intro/workflows/data-acquisition#back-to-pool).

<a id="drag-priority" />

## Why did dragging a step change its priority?

With **Sort by Queue Position** on, moving ahead of more urgent work can raise operation priority; moving behind can lower it. In the same queue, passing equally urgent work can change it by one company level too, if a suitable level fits. Only the moved operation changes. For a split step, all parts show the new priority, but other queues keep their order. See [queue and priority behaviour](/en/platform-intro/pages/assignment-planner#queue-order-and-operation-priority).

<a id="priority-moves-card" />

## Why did my card move when I changed its priority?

In queue-position mode, changing the **OP** chip can move the card past work that is less urgent when raised, or more urgent when lowered. Equal-priority cards keep their relative order. For a split step, its parts can move in other accessible queues too. Administrators can turn this off under **Admin Panel → Priority Levels → Queue order and operation priority stay in step**. Follow [set an operation priority](/en/platform-intro/workflows/assignment-planner#set-an-operation-priority-and-filter-the-plan).

<a id="drag-priority-undo" />

## Does Undo put my dragged card back?

**Undo** in a drag’s priority-change notice restores the previous operation priority and keeps the card where you dropped it. Drag the card again if you also want to change its place; that can change the priority again. This differs from undoing a whole-queue sort. See [reorder work and check its priority](/en/platform-intro/workflows/assignment-planner#reorder-work-and-check-its-priority).

<a id="priority-direction" />

## Who decides whether a smaller priority number is more urgent?

Administrators choose **Higher number = more urgent** or **Lower number = more urgent** under **Admin Panel → Priority Levels → How priorities are used → Which number is more urgent?** Each change saves immediately. SAP presets select higher numbers first; Epicor and Infor select lower numbers first. Resetting the levels restores higher numbers first. Your own sorting-rule directions remain unchanged. Follow [company priority setup](/en/platform-intro/workflows/assignment-planner#set-how-the-company-uses-priorities).

<a id="running-queue-position" />

## Can I move a running step down the Planner queue?

Yes. With **Sort by Queue Position** on, running and on-hold steps keep the place you set, including their queue number. You can reorder running work within its column. Stop it on the machine before moving it to another destination. **Re-sort** also sorts running and on-hold work. The search in **Improve plan** keeps that work in place. See [queue sorting](/en/platform-intro/pages/assignment-planner#queue-position-and-sorting-rules).

<a id="forecast-explanation" />

## Why is my step expected to end at that time?

Hover over the Planner card’s date tab or small clock. **Why this time** names the machine, earlier work, or shift it waits for. **Earlier operations of this order** shows preceding work, even on other machines. Read **Based on** for assumptions about long holds, missed starts, or missing planning details. If details fail to load, hover again. Follow [review Forecaster warnings](/en/platform-intro/workflows/assignment-planner#review-forecaster-warnings-before-changing-the-plan).

<a id="no-forecast" />

## Why does my card say No forecast?

The step is still in a hall pool, or the forecast is not available right now. Hover over **No forecast** to read the reason. Pool work gets a forecast once it is assigned to a machine. Long-held, never-started, and undated machine steps now get expected times with assumption notes. If an earlier step has no machine, a later step can still have a forecast that is too optimistic. See [forecast explanations](/en/platform-intro/pages/assignment-planner#explain-an-expected-end).

<a id="planner-updates" />

## Why do cards move or briefly light up without me refreshing?

The Planner updates forecasts after saves and checks for schedule changes about every minute. Cards slide when their order changes; a dropped card and changed forecast marker briefly highlight. These cues do not change status. Updates pause while you drag, save moves, or use a sorting dialog, an assignment dialog, or the **Back to pool** dialog. With reduced motion enabled on your device, outlines replace movement. See [board updates](/en/platform-intro/pages/assignment-planner#follow-updates-on-the-board).

<a id="planner-machine-link" />

## How do I open a machine from the Planner?

Click the machine name in its column header. Ctrl-click or middle-click opens it in a new tab. Hall-pool names are not links. See [Machine Details](/en/platform-intro/pages/machine-details).

<a id="improve-plan-options" />

## How do I find a sequence with fewer late orders?

Open the sparkle **Improve plan** in a Planner machine header or in Gantt. Under **1 · Choose an option**, compare **Best operation sequence** with the fixed rules. The figures compare late orders and delay after saving with today. Review **2 · What changes**, then use **Save as plan**. [Follow the steps](/en/platform-intro/workflows/assignment-planner#compare-and-save-a-plan).

<a id="keep-place" />

## How do I stop a proposal from moving one operation?

Clear **Can move** for that operation in **Re-sort**, **Best operation sequence**, or the existing machine work in **Distribute to machines**. It keeps its exact place. The searched table first shows only operations that change place or whose status changes. **Show all (N more operations)** shows the rest, including unchanged machines; **Show only the changes** returns to the shorter list. A machine group’s checkbox covers its whole queue. Changed expected ends outside your selection appear under **Also changes expected ends on other machines**. Fixed-rule choices in **Improve plan** have no such control. See [planning choices](/en/platform-intro/pages/assignment-planner#choose-an-option).

<a id="proposal-priorities" />

## Will Improve plan change my priorities?

**Keep priorities** leaves priorities unchanged. **Least delay** and **Fewest changes** can change operation priorities as shown in the proposal. Order priorities never change. Turning off **Queue order and operation priority stay in step** leaves operation priorities unchanged for all searched options. See [option effects](/en/platform-intro/pages/assignment-planner#choose-an-option).

<a id="forecast-queue-rule" />

## Why does dragging cards leave the expected end unchanged?

Your forecast may follow planned dates or delivery dates instead of the queue. Hover over **Manual queue order** for the explanation; it replaces the separate forecast banner. The chip appears only while **Filter & Sort → Sort by Queue Position** is on. With **Follow planned dates**, **Improve plan** can also set new planned dates so the forecast follows the proposal. With **Delivery date first**, the forecast chooses the sequence itself; the Planner hides **Improve plan** and **Distribute to machines**. See [forecast rules and dragging](/en/platform-intro/pages/assignment-planner#when-dragging-does-not-change-expected-ends).

<a id="proposal-dates" />

## Why does the proposal change more planned dates than positions?

With **Follow planned dates** or **Follow the queue, not before the planned date**, saving **Best operation sequence** also sets new planned dates for waiting operations on reordered machines, so the forecast follows the new sequence. Other waiting operations may start at different times even if their positions stay the same. The selected option shows how many planned dates change; check this before **Save as plan**. With **Follow the queue**, saving the sequence sets no planned dates; any operation-priority changes remain as shown. Original operation dates and delivery dates stay unchanged; **Undo** restores the saved plan changes. See [review and save](/en/platform-intro/pages/assignment-planner#review-and-save).

<a id="distribute-pool" />

## Can the Planner choose machines for waiting pool work?

Yes. With planning access and **Sort by Queue Position** on, open **Distribute to machines** in the hall-pool header. Choose machines and pool operations with **Place**, review destinations, then select **Apply this sequence**. Existing machine work keeps its relative sequence. **Undo** returns placed work to the pool in its previous order. [Follow the steps](/en/platform-intro/workflows/assignment-planner#distribute-pool-work).

<a id="pool-stays" />

## Why does some work stay in the pool?

Read the reason beside the operation. No machine may be selected, its earlier operation may also stay in the pool, every placement may delay other orders, or the search may have stopped before reaching it. Clearing **Place** also leaves it in the pool. Try **Search longer** when offered if the search stopped early. See [pool distribution](/en/platform-intro/pages/assignment-planner#distribute-pool-work-to-machines).

<a id="pool-hidden-work" />

## Why does distribution include work I cannot see on the board?

The proposal uses the whole waiting hall pool, including work hidden by board filters or not yet shown. Review its complete list and clear **Place** for anything you want to leave in the pool. See [pool selection](/en/platform-intro/pages/assignment-planner#distribute-pool-work-to-machines).

<a id="proposal-unavailable" />

## Why can I not save the proposal yet?

Wait while **Updating…** recalculates after a machine, **Can move**, or **Place** change. If every operation must keep its place, allow some to move. If a plan or pool conflict appears, choose **Recalculate** and review again. A search may also find no better result; use **Search longer** when offered. See [review and save](/en/platform-intro/pages/assignment-planner#review-and-save).

<a id="proposal-expected-end" />

## Are the before and after times new delivery dates?

No. The information icon beside **Expected end** explains that now is the forecast with today’s sequence and after is the forecast if you apply the proposal. Neither time is the planned end or the delivery date; those are in the details. Click the row or **Details** for the planned end, delivery date, full verdict, and assumptions. Delivery dates do not change. See [review and save](/en/platform-intro/pages/assignment-planner#review-and-save).

<a id="resort-by-date" />

## Can I sort a queue by delivery date?

Yes. Open **Re-sort → 1 · Sort by → Delivery date**. The earliest dates come first; missing dates come last. You can also choose **Planned end**, **Order date**, **Order priority**, or **Operation priority**. Clear **Can move** for operations that must keep their place, then review and apply. See [Re-sort a Queue](/en/platform-intro/workflows/assignment-planner#re-sort-a-queue).

<a id="operation-wording" />

## Why do English labels now say operation instead of step?

Both refer to a production operation within an order. English labels now use “operation” consistently, for example **Operations of this order** and **Show operations**. The wording does not create extra work or change the operation sequence. See the [operation glossary](/en/platform-intro/concepts/glossary#op-ag).

<a id="shared-pda-settings" />

## Who can give several BDE pages the same settings?

Administrators can open **Admin Panel → BDE access templates → New template**, select machines, and choose required fields, highlights, optional fixed sorting and refresh, and allowed actions. Follow [Make the BDE Page the Same on Several Machines](/en/platform-intro/workflows/bde-access-templates).

<a id="template-name-taken" />

## Why can’t I save my template name?

A name is required, with up to 80 characters, and must be unique within your company. Capitalisation and spaces before or after the name do not make it different: “Saws” and “ saws ” count as the same name. Names in other companies do not count. If you see **A template with this name already exists.**, choose another name. See [BDE Access Templates](/en/platform-intro/pages/bde-access-templates#what-you-can-do).

<a id="locked-pda-settings" />

## Why can’t I hide a field or change sorting or automatic refresh?

The machine may use a template. **Set by the template** marks required choices. **Sorting is set by the template** means sorting is fixed here. You can still choose other fields and highlights. Ask an administrator to change the shared choices in [BDE Access Templates](/en/platform-intro/pages/bde-access-templates).

<a id="template-highlights" />

## Why is a field set to always be highlighted still missing?

**Always highlighted** only adds a highlight when the field is visible. Show the field in **Card Display Settings**, or ask an administrator to also select it under **Always shown**. See [template display settings](/en/platform-intro/pages/bde-access-templates#display-settings).

<a id="hidden-pda-actions" />

## Why can’t I change an order’s status or take work from the pool?

The machine’s template can hide status changes, taking or returning pool work, and adding orders. These limits apply to administrators too. Stopping and choosing **Hold** or **Completed**, and booking quantities, still work. **PDA Assist** also stays available as before. Ask an administrator to review **Allowed on the BDE page**. See [allowed actions](/en/platform-intro/pages/bde-access-templates#allowed-actions).

<a id="read-only-pda-details" />

## Why can I read intervals and notes but not correct them?

The template can turn off **Correct interval times and quantities** or **Edit notes and order details** on this machine’s BDE page. The information stays readable, but editing controls are hidden or unavailable. Ask an administrator to review the [template’s allowed actions](/en/platform-intro/pages/bde-access-templates#allowed-actions).

<a id="template-refresh" />

## When will my open BDE page show a changed template?

At its next automatic refresh, every 5 minutes unless another interval is set. Use the page’s refresh button or reload the page to pick up changes immediately. Other devices do not update instantly; a screen left open keeps the old choices until one of these happens. This also applies when a template is assigned or removed. See [changes and limits](/en/platform-intro/pages/bde-access-templates#changes-and-limits).

<a id="template-personal-choices" />

## Will I lose my own settings when a template changes or is deleted?

No. Your personal choices stay saved. Removing a machine from a template or deleting the template returns it to personal settings. Assigning it to another template applies that template’s requirements instead. Each machine can use only one template. Follow [Make the BDE Page the Same on Several Machines](/en/platform-intro/workflows/bde-access-templates).

<a id="template-other-pages" />

## Why can I still use an action in the Planner when it is hidden on the BDE page?

BDE access templates only control Data Acquisition V3. They do not change actions on other pages or grant page or machine access. See [template limits](/en/platform-intro/pages/bde-access-templates#changes-and-limits).

<a id="setting-explanations" />

## Where have the explanations for templates and priorities gone?

Open the information icon beside the title in **Admin Panel → BDE access templates** or **Admin Panel → Priority Levels**. Explanations now appear there instead of below the title. This also covers **Which number is more urgent?** and **Queue order and operation priority stay in step**. See [Admin Panel](/en/platform-intro/pages/admin-panel#how-priorities-are-used).

<a id="gantt-settings" />

## Where do I change the Gantt bars and row height?

Open **View options → Board**. Use **Bars show** for **Expected times** or **Planned dates**, and **Row height** for the space each row uses. These choices are your own and apply immediately. The information icon beside **Bars show** explains the choice. Only Admins can change company settings under **View options → Planning** and choose **Save**. See [Gantt view controls](/en/platform-intro/pages/assignment-gantt#view-controls-and-limits).

<a id="gantt-planning-access" />

## Why are Improve plan and Re-sort missing in Gantt?

Both actions require planning access: an Admin account, or a User with access to **Orders & Products**. Opening Gantt itself requires **Assignment Planner** page access, unless you are an Admin. Without planning access, Gantt hides **Improve plan** in the toolbar and machine rows and **Re-sort** in machine rows. Access to the page alone does not make these actions available. See [Gantt planning actions](/en/platform-intro/pages/assignment-gantt#compare-queue-orders-before-saving).

<a id="delivery-sequence-disabled" />

## Why is Best operation sequence greyed out?

With **Delivery date first**, a searched sequence cannot change expected ends. In Gantt, **Best operation sequence** is therefore unavailable and no search starts. With planning access, **Improve plan** still lets you compare and save the fixed rules. Follow [Compare and Save a Plan](/en/platform-intro/workflows/assignment-planner#compare-and-save-a-plan).

<a id="gantt-undo-not-saved" />

## Why did the Gantt board reload after I chose Undo?

If **Undo** after **Improve plan** or **Re-sort** cannot be saved, Gantt shows **The old sequence could not be put back. The board now shows the current plan.** and reloads the board. Do not assume the previous plan was restored. Review the current order and dates before making another change. See [compare and save a plan](/en/platform-intro/workflows/assignment-planner#compare-and-save-a-plan).

<a id="forecast-hint-location" />

## Where has the note about forecasts following planned dates gone?

The separate banner and its dismiss button have been removed. Hover over **Manual queue order** in Assignment Planner. The chip appears only while **Filter & Sort → Sort by Queue Position** is on. For forecasts following planned or delivery dates, the explanation says that moving cards changes order and priority, not expected ends, and that **Improve plan** can set new planned dates. See [forecast rules and dragging](/en/platform-intro/pages/assignment-planner#when-dragging-does-not-change-expected-ends).
