## Understand Your Production Metrics

The Watchmen Platform combines production quantities and machine time to help you understand your results. Use the same machine and reporting period when comparing them. Watchmen uses time-based Availability and Performance definitions that differ from textbook OEE. The [calculations reference](/en/platform-intro/concepts/calculations) distinguishes confirmed definitions from illustrative formulas.

### One Example for All Four Metrics

Imagine a machine observed over seven hours:

| Machine state | Meaning in this example | Duration |
| --- | --- | --- |
| Production | Making parts | 3 hours |
| Preparation | Setting up for production | 1 hour |
| Idle | Switched on, but neither producing nor preparing | 1 hour |
| Off | Switched off | 2 hours |
| **Total** | **All four states in the selected period** | **7 hours** |

The machine produces **100 units**: **95 good units** and **5 scrap units**. Preparation is also called setup; idle time and switched-off time are separate states.

<a id="quality" />

## How Is Quality Calculated?

A **quantity-based quality rate** is the percentage of produced units that are good. Scrap reduces it. The following arithmetic explains this rate; the dashboard tooltip separately shows a configured quality of 95%. It does not confirm automatic calculation from these quantities.

**Formula:** Quality (%) = good units / total produced units × 100.

In our example, total production includes the 95 good units and the 5 scrap units:

**95 / 100 × 100 = 95% quality.**

This means 95 out of every 100 produced units are good. Review quantities and scrap in [Data Acquisition (PDA)](/en/platform-intro/pages/data-acquisition) and the [order details](/en/platform-intro/pages/order-detail).

### Why Does Quality Show 95% Without Actual Good-Unit Data?

The dashboard tooltip states that quality is **set at 95%** and tells you to contact an admin to change it. The setting location is not established by the frontend reference.

Automatic replacement with actual good-unit data, per-order overrides, and planned-quantity fallback are not confirmed by the frontend reference. Treat the configured 95% as a configured value, not proof that 95% of units passed inspection. Continue recording good and scrap quantities for production analysis.

See [ERP/PDA data ingestion](/en/erp-bde-integration) for integration context and [Run Data Acquisition](/en/platform-intro/workflows/data-acquisition) for recording production data.

<a id="availability" />

## How Is Availability Calculated?

**Availability** is the share of the selected period spent producing. In this calculation, the denominator includes production, preparation, idle, and off time.

**Formula:** Availability (%) = production time / total recorded time × 100. The example total consists of production + preparation + idle + off time; Unknown-time treatment is not established here.

For our seven-hour example:

**3 / (3 + 1 + 1 + 2) × 100 = 42.86% availability.**

The machine produced for about 43% of the observed period. Preparation, idle, and off time all reduce this value because they are included in total time but not production time.

### Why Is Availability Lower Than Expected?

Check the selected date or shift and how the timeline splits time between states. A period containing two hours of off time gives a different result from one containing only switched-on time.

Use [Machine Details](/en/platform-intro/pages/machine-details) to review date and shift context, and [Timeline Analysis](/en/platform-intro/pages/timeline-analysis) to examine the time distribution.

<a id="performance" />

## How Is Performance Calculated?

**Performance** compares production plus preparation time with all switched-on time. Switched-on time includes idle time; off time is excluded.

**Formula:** Performance (%) = (production + preparation time) / (production + preparation + idle time) × 100.

In our example, effective time is **4 hours** and switched-on time is **5 hours**:

**(3 + 1) / (3 + 1 + 1) × 100 = 80% performance.**

This means 80% of switched-on time was spent producing or preparing. The remaining 20% was idle time.

### Does Performance Measure Machine Speed?

This time-based calculation does not compare actual speed with an ideal cycle time. Preparation counts toward performance, even though it does not count toward availability. Use these definitions when comparing the two metrics.

For example, a machine that spends more time preparing can still have high performance while availability remains low. Check the underlying states in [Timeline Analysis](/en/platform-intro/pages/timeline-analysis) before drawing conclusions about output or speed.

<a id="oee" />

## How Is Overall Equipment Effectiveness (OEE) Calculated?

**Overall Equipment Effectiveness (OEE)** combines availability, performance, and quality into one percentage. All three inputs must refer to the same machine and period. The frontend does not establish the exact server formula. The multiplication below is an illustrative calculation; use the dashboard for the reported OEE.

**Formula using decimal ratios:** OEE (%) = availability ratio × performance ratio × quality ratio × 100.

Using the example without rounding intermediate values:

**(3 / 7) × (4 / 5) × (95 / 100) × 100 = 32.57% OEE.**

If you enter percentages as numbers such as 80 and 95, use **OEE (%) = availability (%) × performance (%) × quality (%) / 10,000**. Convert percentages to ratios or use this percentage formula consistently.

### Why Is OEE Lower Than Each Individual Metric?

In the multiplication example, the three ratios multiply. Even 80% performance and 95% quality cannot compensate for only 42.86% availability. Inspect each factor to understand which part of the result needs attention.

### Why Does My Manual Calculation Differ from the Dashboard?

- Match the machine, date range, and shift before comparing values.
- Use unrounded durations and quantities; round only the final result.
- Treat dashboard quality as the configured value unless its data source is confirmed; the tooltip states 95%.
- Check the state definitions, especially preparation and off time.
- If a denominator is zero, such as no produced units or no switched-on time, the corresponding formula cannot give a meaningful percentage. Review the underlying data first.

## How do I find which orders ran on a machine last week?

Open machine history, choose the period, and find **Orders**. Click a bar or list row to see the step and its order route. Use **Open order** for the full order if you have access. Follow [Review Machine History](/en/platform-intro/workflows/machine-history-review).

<a id="booked-states" />

## Why is booked production time different from the machine’s production time?

**Booked time** describes how work was recorded as preparation or production. **Machine states** describes what the machine actually did during those bookings, including idle or off time. See [Machine History](/en/platform-intro/pages/machine-history).

<a id="step-totals" />

## Why are the step’s totals larger than the bars in my selected period?

The step’s details include all its recorded work and produced quantities on this machine. The chart includes only the displayed period. Hover over a bar for the time and machine states of that stretch. See [Machine History](/en/platform-intro/pages/machine-history).

<a id="history-limit" />

## Why can I see only the last three months of orders?

The orders chart and its machine-state row show at most the last 3 months of the selected period. Choose an earlier period to review older work. Follow [Review Machine History](/en/platform-intro/workflows/machine-history-review).

<a id="empty-orders" />

## Does an empty Orders section mean the machine was off?

No. **No orders were worked on this machine in this period.** means no order work was booked for that period. It appears centred in the empty section. Missing state information has its own message. See [Machine History](/en/platform-intro/pages/machine-history).

<a id="order-scrolling" />

## How do I stop the order cards moving while I read them?

Hover over the list or focus it with the keyboard. Scrolling or touching it pauses movement temporarily. Your reduced-motion preference turns automatic movement off; you can still scroll by hand. See [Machines](/en/platform-intro/pages/machines).

<a id="history-patterns" />

## Can I distinguish idle and off in history without relying on colour?

Yes. Enable **Accessibility patterns** in your profile or in the machine legend. History uses dots for idle and diagonal lines for off in its state row and legend. See [User Profile](/en/platform-intro/pages/user-profile).

<a id="ongoing-state" />

## Does the time since the last machine-state change count in my totals?

Yes, **Machine History** for any range and the [**Timeline** report](/en/platform-intro/pages/timeline-analysis) over several days count that time. Today counts up to now, subject to the [sensor signal rules](/en/help-center/faq/production-metrics#missing-signal).

<a id="missing-signal" />

## Why does the last machine state stop counting or turn into off time?

When the sensor sends no signal for more than 20 minutes, the last state counts only until the last signal. For a [sensor powered by the machine](/en/platform-intro/pages/machine-configuration), that silent time counts as **Off**.

<a id="more-idle-off-time" />

## Why does Machine History show more idle or off time for past weeks or months now?

Since October 18, 2026, **Machine History** and the [**Timeline** report](/en/platform-intro/pages/timeline-analysis) over several days count time since the last state change, so days spent idle or off show that time instead of almost nothing. Availability and OEE for those days can change; the [20-minute rule and the rule for sensors powered by the machine](/en/help-center/faq/production-metrics#missing-signal) still apply.

<a id="edit-interval" />

## How do I correct the start or end of an interval?

In Data Acquisition V3, open the order’s interval list and tap the start or end time once. The editor opens on **Start** or **End**, matching the time you tapped. Use the wheels, **−** and **+**, or **−5 min** and **+5 min**, then select **Save**. The pencil opens the editor on **Quantities** to correct quantities. In Order Management, choose **Edit interval** from the interval’s three-dot menu, then select **Start** or **End**. Follow [Correct an Interval](/en/platform-intro/workflows/data-acquisition#correct-an-interval).

<a id="interval-keyboard" />

## Can I type the time and quantities instead of turning wheels?

Yes. On a computer, type hours, minutes, and quantities with the keyboard. You can also use **−** and **+** for time changes. Touch screens offer time wheels and a number pad. **−5 min** and **+5 min** are available on both. See [interval controls](/en/platform-intro/pages/data-acquisition#review-and-change-an-interval).

<a id="interval-device-controls" />

## Why do I see − and + buttons instead of the wheel?

The editor chooses the controls for your device. Touch screens show wheels. With a mouse or touchpad, it shows **−** and **+**, and you can type hours and minutes. If a touch device is not recognised, it shows **−** and **+**, which also work by touch. **−5 min** and **+5 min** are available on both. See [interval controls](/en/platform-intro/pages/data-acquisition#review-and-change-an-interval).

<a id="interval-running-end" />

## Why can’t I end a running interval from Order Management?

**Still running** means no end has been recorded. Previously, entering an end in Order Management stopped the interval. Now **End** shows the still-running note. The editor cannot end the interval or clear a saved end. Use the normal stop action in Data Acquisition, then correct the end if needed. Follow [Run Data Acquisition](/en/platform-intro/workflows/data-acquisition).

<a id="interval-type" />

## Can I change an interval from production to preparation?

Yes. Choose **Preparation** or **Production** in the editor and select **Save**. A running interval cannot switch to **Production** or **Preparation** if another interval of that type is already running on the same order. Check the other interval and stop it through the normal controls if that work has ended. Finished intervals do not have this restriction. See [editing limits](/en/platform-intro/pages/data-acquisition#limits-when-editing).

<a id="interval-save" />

## Why is Save unavailable when I edit an interval?

**Save** is unavailable when nothing changed, a time error remains, or saving is in progress. When changing times, keep the end after the start and both times out of the future. If **Saving…** appears, wait for the result. See [Correct an Interval](/en/platform-intro/workflows/data-acquisition#correct-an-interval).

<a id="interval-cumulative" />

## Do I enter the full counter reading when correcting a cumulative quantity?

Yes. Keep the full machine counter reading in cumulative mode, rather than the amount made during this interval. The editor starts with the saved reading so you can correct it. See [recorded interval editing](/en/platform-intro/pages/order-detail#edit-recorded-intervals).

<a id="interval-cancel" />

## Why did my changes save after I pressed Cancel?

If you already selected **Save**, the save can still finish after **Cancel**. The interval table updates with the saved result. Check it before making another correction. Before saving starts, **Cancel** discards your edits. See [interval editing](/en/platform-intro/pages/data-acquisition#review-and-change-an-interval).

<a id="interval-load" />

## Why won’t my running interval open for editing?

In Order Management, the editor first loads the saved interval quantities. If this fails, it stays closed and shows **The interval could not be loaded. Please try again.** Try opening the interval again. See [recorded interval editing](/en/platform-intro/pages/order-detail#edit-recorded-intervals).
