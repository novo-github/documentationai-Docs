<a id="manage" />

## Wer kann Stillstandsgründe ändern?

Nur Admins können Gründe anlegen, bearbeiten, löschen oder einschränken. Nutzen Sie **Maschineneinstellungen → Stillstandsgründe** oder **Admin-Panel → Analysatoren konfigurieren → Stillstandsgründe**. Das Formular zeigt die Grunddetails links und **Verfügbar auf Maschinen** rechts. Das Informationssymbol neben dem Listentitel erklärt feste Listen. Änderungen an einem gemeinsamen Grund gelten für alle Maschinen. Folgen Sie [Stillstandsgründe erstellen und verwalten](/de/platform-intro/workflows/timeline-reason-creation).

<a id="missing" />

## Warum fehlt ein Stillstandsgrund an meiner Maschine?

Die Maschine nutzt möglicherweise **Nur ausgewählte Gründe**, oder ein Admin hat die Verfügbarkeit geändert. Wählen Sie einen verfügbaren Grund oder lassen Sie die Liste prüfen. Eine geöffnete BDE-Seite übernimmt Änderungen beim nächsten Aktualisieren. Auch eine abgelehnte Auswahl aktualisiert die Liste. Siehe [Betriebsdatenerfassung](/de/platform-intro/pages/data-acquisition).

<a id="future" />

## Warum erscheinen neue Gründe auf einer Maschine, aber nicht auf einer anderen?

**Alle Gründe (Standard)** enthält spätere Ergänzungen. Eine feste Liste enthält sie nicht. Wenn Sie unter **Verfügbar auf Maschinen** eine Maschine abwählen, die bisher alle Gründe anbietet, erhält sie eine feste Liste der übrigen aktuellen Gründe. Siehe [Maschinenkonfiguration](/de/platform-intro/pages/machine-configuration).

<a id="copy" />

## Kann ich dieselbe Grundauswahl für mehrere Maschinen verwenden?

Ja. Admins können unter **Stillstandsgründe** die Auswahl **Auf andere Maschinen übertragen**. Prüfen Sie vor der Bestätigung die aktuelle Auswahl und die Zielmaschinen. Deren bisherige Listen werden ersetzt. Das geht auch mit einer leeren festen Liste. Dann bietet keine der gewählten Maschinen einen Grund an. Folgen Sie [Stillstandsgründe erstellen und verwalten](/de/platform-intro/workflows/timeline-reason-creation).

<a id="code" />

## Was bedeutet der Code neben einem Stillstandsgrund?

Es ist ein optionaler Unternehmenscode, etwa F12, zum Erkennen eines Grundes. Codes sind im Unternehmen eindeutig und verwenden Großbuchstaben. Kategorien gruppieren die Auswahl. Diagrammerklärungen zeigen vollständigen Code, Namen und Kategorie. Siehe [Administrationsbereich](/de/platform-intro/pages/admin-panel).

<a id="last-reason" />

## Kann ich den letzten Stillstandsgrund einer Maschine entfernen?

Ja. Wählen Sie als Admin die Maschine unter **Verfügbar auf Maschinen** ab und speichern Sie. Hat sie keinen weiteren ausgewählten Grund, bietet sie keinen an. Auch das Löschen ihres letzten ausgewählten Grundes lässt sie ohne Grund. Sie wechselt dadurch nicht zu allen Gründen. Siehe [Verfügbarkeit einstellen](/de/platform-intro/pages/admin-panel).

<a id="delete" />

## Was passiert beim Löschen eines Stillstandsgrundes?

Der Löschhinweis zeigt, wo der Grund verwendet wird. Frühere Stillstände bleiben ohne Ersatzgrund erhalten. Diagramme und Berichte nach Stillstandsgründen werden für die betroffenen Tage aktualisiert. Bereits erhaltene Berichte bleiben unverändert. Der Grund wird auch aus Maschinenlisten, Regeln für Stillstandsgründe, Standardgründen und Pausen entfernt. Pausenzeiten bleiben erhalten. Eine eingeschränkte Maschinenliste bleibt eingeschränkt, auch wenn sie ihren letzten Grund verliert. Um nur eine Zuordnung zu entfernen, nutzen Sie **Grund entfernen**. Folgen Sie [einen gemeinsamen Grund löschen](/de/platform-intro/workflows/timeline-reason-creation#delete-reason).

<a id="create-retry" />

## Der Grund wurde angelegt, seine Maschinen aber nicht gespeichert. Soll ich ihn erneut anlegen?

Nein. Der Grund existiert bereits. Prüfen Sie im selben Formular die Maschinenliste und speichern Sie erneut. Wurde die Auswahl anderswo geändert, prüfen Sie vor einem weiteren Versuch die neu geladenen Angaben. Siehe [Stillstandsgründe erstellen und verwalten](/de/platform-intro/workflows/timeline-reason-creation).

<a id="live-reason" />

## Warum verschwindet mein gewählter Grund beim laufenden Stillstand?

Das war ein Anzeigeproblem, das mit v1.5.153 behoben wurde. Ihr gewählter Grund bleibt jetzt nach einer Seitenaktualisierung im Tooltip des laufenden Stillstands in der Timeline sichtbar, auch wenn der Stillstand vor den letzten 8 angezeigten Stunden begonnen hat. Siehe [einen Stillstandsgrund wählen](/de/platform-intro/pages/data-acquisition#einen-stillstandsgrund-wählen).

<a id="after-restart" />

## Kann ich kurz nach dem Wiederanlaufen noch einen Grund wählen?

Ja. Öffnen Sie den beendeten Stillstand in der Timeline und wählen Sie dort seinen Grund. Während die Maschine läuft, merken die Grundkacheln jetzt einen Grund für kommende Stillstände vor. Ein für den aktuellen Stillstand gewählter Grund bleibt beim Ende erhalten. Folgen Sie [Stillstand mit einem verfügbaren Grund beschriften](/de/platform-intro/workflows/data-acquisition#stillstand-mit-einem-verfügbaren-grund-beschriften).

<a id="pre-set" />

## Kann ich einen Grund wählen, bevor die Maschine steht?

Ja. Öffnen Sie auf der BDE-Seite **Stillstandsgrund** und tippen Sie einen Grund an, während die Maschine läuft. Jeder Stillstand, der in den nächsten 15 Minuten beginnt, erhält ihn automatisch. Das gilt auch für mehrere Stillstände. Folgen Sie [einen Stillstandsgrund vormerken](/de/platform-intro/workflows/data-acquisition#next-downtime-reason).

<a id="pre-set-during-stop" />

## Kann ich den nächsten Grund vormerken, während die Maschine schon steht?

Ja. Wählen Sie **Vorgemerkter Stillstand** und tippen Sie einen Grund an. Er gilt für neue Stillstände nach dem Wiederanlauf. Der aktuelle Stillstand behält seinen eigenen Grund. Die 15 Minuten beginnen beim Antippen. Die Vormerkung kann daher vor dem Wiederanlauf ablaufen. Jeder neue Stillstand beginnt mit **Aktueller Stillstand** und bleibt dabei, bis Sie wechseln. Siehe [aktuelle und kommende Stillstände](/de/platform-intro/pages/data-acquisition#next-downtime-reason).

<a id="change-pre-set" />

## Wie ändere oder beende ich eine Vormerkung?

Mit **−5 Min.** oder **+5 Min.** in der Leiste unten im mittleren Teil der BDE-Seite passen Sie die Zeit an, bis höchstens 2 Stunden im Voraus. Bei 6 Minuten oder weniger ist die Verkürzung gesperrt. Tippen Sie zum Beenden auf das Kreuz in der Leiste. Zum Ändern des Grundes tippen Sie eine andere Kachel an, während die Maschine läuft oder **Vorgemerkter Stillstand** ausgewählt ist. Folgen Sie [eine Vormerkung verwalten](/de/platform-intro/workflows/data-acquisition#next-downtime-reason).

<a id="remove-current-reason" />

## Wie entferne ich den Grund des aktuellen Stillstands?

Wählen Sie **Aktueller Stillstand** und tippen Sie auf das Kreuz auf der gewählten weißen Grundkachel. Damit entfernen Sie den Grund des laufenden Stillstands. Endet er ohne Grund, können die Regeln für Stillstandsgründe wieder greifen. Bei einer Vormerkung beendet das Kreuz auf der Kachel stattdessen die Vormerkung. Siehe [Grundauswahl und Vormerkung](/de/platform-intro/pages/data-acquisition#next-downtime-reason).

<a id="pre-set-long-stop" />

## Behält ein langer Stillstand den vorgemerkten Grund nach den 15 Minuten?

Ja. Ein Stillstand, der während der Vormerkung beginnt, behält den Grund für seine gesamte Dauer, auch beim Wechsel zwischen Leerlauf und Aus. Wenn Sie die Vormerkung mit ✕ beenden, behalten Stillstände ihren bereits erhaltenen Grund ebenfalls. Siehe [so funktionieren vorgemerkte Stillstandsgründe](/de/platform-intro/pages/data-acquisition#next-downtime-reason).

<a id="pre-set-priority" />

## Können Pausengründe oder Regeln meinen vorgemerkten Grund überschreiben?

Nein. Ein vorgemerkter Stillstandsgrund zählt als Ihre eigene Auswahl, genau wie ein während des Stillstands gewählter Grund. Pausengründe und automatische Regeln für Stillstandsgründe ersetzen ihn nicht. Siehe [Stillstandsgründe vormerken](/de/platform-intro/pages/data-acquisition#next-downtime-reason).

<a id="pre-set-access" />

## Wer kann einen Grund vormerken?

Maschinenbediener, User und Admin können einen Stillstandsgrund vormerken, wenn sie bereits Gründe auf der BDE-Seite der Maschine wählen können. Dafür ist keine Admin-Einstellung nötig; folgen Sie [einen Stillstandsgrund vormerken](/de/platform-intro/workflows/data-acquisition#next-downtime-reason).

<a id="changed-totals" />

## Warum sehen meine Summen je Stillstandsgrund seit dieser Aktualisierung anders aus?

Seit dem 5. November 2026 (v1.5.153) greifen **Regeln für Stillstandsgründe** bei mehr Stillständen in Leerlauf und Aus, wenn der Maschinenbediener keinen Grund gewählt hat. Bei Maschinen mit Regeln kann dadurch mehr Stillstandszeit einen Grund erhalten. Die Summen je Grund in Berichten und Diagrammen können sich deshalb ändern. Stillstände vor der Aktualisierung bleiben unverändert. Siehe [automatische Regeln](/de/platform-intro/workflows/timeline-reason-creation#automatische-regeln).

Seit dem 6. November 2026 (v1.5.155) können Admins außerdem automatische Pausengründe einschalten. Danach können passende beendete Stillstände einen Pausengrund statt eines Regelgrundes erhalten. Wird nur die Pause gekennzeichnet, können sich Anzahlen und Durchschnittswerte ändern. Die Auswahl einer Person bleibt erhalten. Siehe [Pauseneinstellungen](/de/platform-intro/pages/break-settings).

<a id="reason-priority" />

## Was hat Vorrang: mein gewählter Grund oder die Regeln?

Ein vom Maschinenbediener gewählter oder von Hand gesetzter Grund hat Vorrang. Ist die [automatische Pausenkennzeichnung](/de/platform-intro/pages/break-settings) eingeschaltet, folgt der Grund einer passenden Pause. **Regeln für Stillstandsgründe** gelten für die übrige Zeit in Leerlauf oder Aus. Ohne passenden Grund bleibt die Zeit unbeschriftet.

<a id="split-break-downtime" />

## Warum zählt ein Stillstand jetzt als mehrere?

**Nur die Pause kennzeichnen (empfohlen)** kann einen Stillstand in die Pause und die Zeit davor oder danach aufteilen. Jeder Abschnitt zählt bei Anzahlen und Durchschnittswerten je Grund einzeln. Die Gesamtzeit je Maschinenzustand bleibt gleich. **Den ganzen Stillstand kennzeichnen** vermeidet diese Aufteilung, kann aber eine lange Störung unter dem Pausengrund verbergen. Siehe [automatisch gekennzeichnete Pausen](/de/platform-intro/pages/timeline-analysis#automatisch-gekennzeichnete-pausen-lesen).

<a id="no-reasons" />

## Warum kann ich auf meiner Maschine keinen Stillstandsgrund wählen?

Ein Admin kann **Nur ausgewählte Gründe** ohne ausgewählten Grund speichern. Die Maschine bietet dann keine Gründe an. Das Entfernen oder Löschen ihres letzten ausgewählten Grundes hat dasselbe Ergebnis. Lassen Sie einen Admin **Maschineneinstellungen → Stillstandsgründe** prüfen, benötigte Gründe oder **Alle Gründe (Standard)** wählen und speichern. Folgen Sie [Grundauswahl verwalten](/de/platform-intro/workflows/timeline-reason-creation).

<a id="unavailable-rule" />

## Warum ist ein Grund in meiner automatischen Regel ausgegraut?

Die Maschine bietet diesen Grund nicht mehr an. Er bleibt als **auf dieser Maschine nicht verfügbar** sichtbar, weil diese Regel ihn bereits verwendet. Sie kann ihn aber nicht vergeben. Andere nicht verfügbare Gründe erscheinen nicht in der Auswahl. Öffnen Sie als Admin **Maschineneinstellungen → Regeln für Stillstandsgründe**, wählen Sie einen verfügbaren Grund oder **Kein Grund** und speichern Sie. Folgen Sie [automatische Regeln prüfen](/de/platform-intro/workflows/timeline-reason-creation#automatische-regeln).

<a id="no-machines" />

## Was bedeutet „Keine Maschine“ neben einem Grund?

**Keine Maschine** unter **Verfügbar auf** bedeutet, dass der Grund vorhanden ist, aber auf keiner Maschine angeboten wird. Ein Admin kann ihn bearbeiten, unter **Verfügbar auf Maschinen** Maschinen auswählen und speichern. Siehe [Verfügbarkeit von Gründen](/de/platform-intro/pages/admin-panel#stillstandsgründe-verwalten).
